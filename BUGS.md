## Open

### A director run that ends on a checkpoint abort drops its dequeued prompt, so each unmirrored issue waits another 24 h and the mirror alert cannot clear (found by the director role 2026-11-22)

- **Symptom:** the dashboard alert `5 open issues on znation/tumwater are waiting for the director to mirror them` (`src/ui/team-alert-status.ts`, key from `unmirrored` in `src/github/github-issues-state.ts`) sat up for hours while the director was running. Each of the mirror's queued issue prompts WAS handed to a director run — `log/events.jsonl` runs 79–83 each pair a `prompt_taken` for a `GitHub issue #N` prompt with a `run_end` of `result: "no_change"` after ~25 minutes and ~50k tokens — and each of those runs ended on a checkpoint abort, so no entry was ever written and no issue was ever declined. The prompt is simply gone: the queue holds nothing for that issue, and the ledger's `queued` record keeps the mirror from offering it again for a full day. On 2026-11-22 the live ledger (`.tumwater/state/github-issues.json`) had all five open issues `trusted: true, mirrored: false` with `queued.at` stamps from 2026-11-21T22:50Z to 2026-11-22T00:23Z, and no `declined` record at all: five issues × one 24 h hold each, served one at a time, is up to five days of this alert with the team burning a director run per round.
- **Reproduce:** offline and deterministic, no model. Build the ctx the same way `test/run-verdict.test.ts` "a checkpoint-abort no_change is not a cut-off and its warning names the real cause" does — `userPrompt` set to a `GitHub issue #…` prompt, `pi` with `finalMessageContentless: true`, `stopReason: "aborted"`, `compacted` false — and call `resolveRunVerdict`. The outcome is `no_change` with `cutOff: undefined`, and the prompt is neither re-queued nor reported lost: the queue file the run took its prompt from stays empty. Live shape: the events/ledger pair above.
- **Cause.** `resolveRunVerdict` calls `ctx.pending.clear()` (src/run/run-verdict.ts) before any arm runs, and `noChangeArm` re-queues only on `diagnosis.cutOff`. `diagnoseNoChange` (src/verdict/no-change.ts) deliberately reports a checkpoint abort as `checkpointAborted` and NOT `cutOff` — the 2026-11-16 fix, correct for role runners, because the session was never compacted and must not be resumed — so an unfulfilled director run falls past `pending.requeueForResume` and its prompt is discarded. The mirror then holds its re-offer on time, not on outcome: `nextIssuePrompt` (src/github/issue-queue.ts) skips any issue whose `queued` record is younger than `QUEUED_RECHECK_MS` (24 h), so a dropped prompt costs a full day per issue before the scan tries it again.
- **Fix direction.** A director run never resumes a session, so an unfulfilled director run must always give its prompt back: re-queue through `pending.requeueForResume` (which routes the director to `requeueUnfulfilled`) on the checkpoint-abort `noChangeArm` path, the same way `quietKillArm` already does. Then make the mirror's hold outcome-aware instead of purely timed: an issue whose director run ended unfulfilled (no mirror push, no `declined` record) should be re-offered on the next poll rather than after 24 h — the `queued` record needs a signal that the run did not settle it. Acceptance: a checkpoint-abort director run leaves its issue prompt back in the queue (assert the queue contents, not just the outcome), and a re-offered issue is not held by the 24 h `queued` record when the previous run neither mirrored nor declined it.
