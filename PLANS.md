### Report window: `tumwater report --since <duration> --until <duration>` totals a bounded past window that ends before now (planned 2026-10-20 by the plan role; independent of every eligible plan; touches src/cli.ts + src/cli/cli-flag-specs.ts + src/cli/cli-args.ts + src/report/report.ts + src/report/report-data.ts + src/report/report-render.ts + src/text/datetime.ts + src/cli/help.ts + docs/cli.md + test/report.test.ts)

**Goal.** `logs` and `history` take `--until <duration>`, so `--since 4d --until 3d` shows one past day (PLANS-DONE.md, "Event log window" and "Run history window"). `report --since` still always ends its window at now. To total what an incident 3 days ago cost (runs, tokens, spend, failures by role), an operator has to ask for `--since 4d` and get every later run mixed in. This plan gives the usage report's `--since` shape the same `--until` bound, with the same rules and wording as `logs`/`history`: it requires `--since`, must be shorter than it, and composes with `--role` and `--json`. When planned, `grep -n -- '--until' src/report/*.ts` printed nothing, and `grep -n 'report.*--until' PLANS.md PLANS-DONE.md BUGS.md` printed nothing.
Out of scope, unchanged: the failure digest (`report --failures --since`), whose `collectFailureReportSince` (src/failure/failure-data.ts) compares against the equal-length window before it, so a bounded window needs its own design; the TUI Report pane (src/ui/tui/tui-pane-report.ts) and `GET /api/report` (src/gui/gui-endpoints.ts), which call `collectReportSince` with three arguments and keep working through the new optional parameter.

**Approach.**
1. src/cli.ts, `case "report"`: the `rejectUnknownArgs("report", …)` list gains `untilFlagSpec("report --until")` right after `sinceFlagSpec("report --since")`, and `untilFlagSpec` is already imported. src/cli/cli-flag-specs.ts: `untilFlagSpec`'s doc comment says "of `logs` and `history`"; make it "of `logs`, `history` and `report`". src/cli/cli-args.ts `parseSinceFlag`: the doc comment's last sentence "logs and history read their `--until` bound through the same idiom" becomes "logs, history and report read their `--until` bound through the same idiom". No code change in either file.
2. src/report/report.ts `cmdReport`: right after `const ms = parseSinceFlag(args, "report --since", REPORT_SINCE_MAX_MS);`, add `const untilMs = parseSinceFlag(args, "report --until", REPORT_SINCE_MAX_MS, "--until");`, then, with the `logs` wording (src/cli/log-commands.ts `cmdLogs`):
   - `if (untilMs !== null && ms === null) fail("report --until requires --since");`
   - `if (untilMs !== null && ms !== null && untilMs >= ms) fail(\`report --until (${durationLabel(untilMs)}) must be shorter than --since (${durationLabel(ms)})\`);`
   - Inside `if (ms !== null)`, before the `--failures` dispatch: `if (untilMs !== null && args.includes("--failures")) fail("report --until does not apply to --failures: the digest compares its window against the equal-length window before it");`
   - Pass `untilMs ?? undefined` as a fourth argument to `collectReportSince`.
   Import `fail` from "../cli/cli-output.js" and `durationLabel` from "../cli/cli-args.js" if they are not imported yet (check with grep first). Add `[--until <duration>]` after `[--since <duration>]` in `cmdReport`'s doc-comment synopsis.
3. src/report/report-data.ts:
   - `SinceReport` gains two optional fields after `fromIso`: `untilMs?: number; // the --until bound; absent when the window ends now` and `toIso?: string; // ISO string of the window end; set only with untilMs`.
   - `collectReportSince(root, sinceMs, role?, untilMs?: number)`: after `const cutoff = now - sinceMs;`, add `const end = untilMs === undefined ? now : now - untilMs;`. The fold loop's skip test becomes `ev.ts < cutoff || ev.ts > now || (untilMs !== undefined && ev.ts >= end)`, so an unbounded window keeps its exact current filter. `coversFullWindow` is unchanged: `--until` does not move the window's far edge. The returned object adds `...(untilMs === undefined ? {} : { untilMs, toIso: new Date(end).toISOString() })` right after `fromIso`, so JSON without `--until` stays as it is. Add a sentence on `untilMs` to the function's doc comment.
4. src/text/datetime.ts: beside `sinceWindowLine`, add `export function boundedWindowLine(since: string, until: string, fromIso: string, toIso: string): string` returning `` `window: ${since} to ${until} ago (since ${formatTimestamp(…fromIso)}, until ${formatTimestamp(…toIso)})` ``, with a one-sentence doc comment naming it as `sinceWindowLine`'s bounded sibling. src/report/report-render.ts `renderSinceReportMarkdown`: when `data.untilMs !== undefined && data.toIso !== undefined`, push `boundedWindowLine(durationLabel(data.sinceMs), durationLabel(data.untilMs), data.fromIso, data.toIso)` instead of the `sinceWindowLine(…)` line. Every other line is unchanged.
5. src/cli/help.ts, the `tumwater report --since <duration> [--role …` stanza: synopsis becomes `tumwater report --since <duration> [--until <duration>] [--role <id>[,<id>...]] [--json]`. Append to its description "; --until <duration> ends that window the given duration ago (requires --since; not with --failures)". Re-wrap to the stanza's column. Shell completion reads flags from the help stanzas (`helpStanzas`, src/cli/completion.ts), so it needs no separate edit.
6. docs/cli.md, "Audit" row: `` `tumwater report --since <duration>` (totals over a trailing window, capped at 7d; `` becomes `` `tumwater report --since <duration> [--until <duration>]` (totals over a trailing window, capped at 7d; `--until` ends that window that long ago, so `--since 4d --until 3d` totals one past day (it requires `--since`, must be shorter than it, and does not combine with `--failures`); ``.

**Files.** src/cli.ts, src/cli/cli-flag-specs.ts, src/cli/cli-args.ts, src/report/report.ts, src/report/report-data.ts, src/report/report-render.ts, src/text/datetime.ts, src/cli/help.ts, docs/cli.md, test/report.test.ts.
