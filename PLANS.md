**Goal.** Pin the one unpinned member of src/collections.ts's string-ordering family in `test/collections.test.ts`. `compareCodeUnits` is the single home of the locale-independent code-unit order that eleven call sites read through, and the rule it carries — `a < b ? -1 : a > b ? 1 : 0` — is the exact contrast its own doc comment draws against `rankByCount`'s `localeCompare` tiebreak: it is a *raw code-unit* order, so the ASCII uppercase block (`"A"`–`"Z"`) sorts before the lowercase block (`"a"`–`"z"`), while `localeCompare` (accent- and case-insensitive) orders them interleaved. A reader who replaced the comparator with `localeCompare` to "unify" the two would pass the existing `rankCountEntries`/`sortByValueDesc` cases and still reorder every `compareCodeUnits` call site. Pin its three branches and the one discriminator pair with plain `assert` in the existing test file.

**Approach.** One file, no new dependency, no invariant edit, no src change. In `test/collections.test.ts` (which already imports from `../src/collections.js`), add `compareCodeUnits` to the import list and add one `test(…)` block, named for the rule (e.g. `"compareCodeUnits orders by raw code unit, not locale"`), with plain `assert.equal` cases whose expected signs are derived from the raw code-unit rule, not from calling the function:
- the three branches: `compareCodeUnits("a", "a")` is `0` (equal → not less, not greater); `compareCodeUnits("a", "b")` is `-1` (`"a" < "b"`); `compareCodeUnits("b", "a")` is `1`.
- the contract that separates it from `localeCompare` — the regression this pin guards against: `compareCodeUnits("Z", "a")` is `-1` (uppercase `0x5A` < lowercase `0x61`), even though `"Z".localeCompare("a")` is positive (`a` first). This is the discriminator: the same two inputs, opposite orders.
- one ASCII punctuation vs letter pair to fix the "raw code unit" reading, not a collation order: `compareCodeUnits("!", "A")` is `-1` (`0x21` < `0x41`).

Each expectation is computed from the definition (the `a < b ? -1 : a > b ? 1 : 0` sign of the raw comparison), not from a call to `compareCodeUnits`, and none re-derives the value by running the code under test.

**Files touched.** `test/collections.test.ts` only — extend the existing `import { … } from "../src/collections.js"` with `compareCodeUnits` and add the one test block. No `src/` file changes; no `docs/invariants.md` edit (no collections section exists).

**Acceptance criteria.**
- Given two equal strings (`"a"`, `"a"`), `compareCodeUnits` returns `0`; given `"a"` and `"b"` it returns `-1`; given `"b"` and `"a"` it returns `1`. (The three comparator branches, pinned by their exact sign.)
- Given `"Z"` and `"a"`, `compareCodeUnits` returns `-1` — the discriminator that `localeCompare` gets opposite, so a regression that routed the comparator through `localeCompare` (the sibling `rankByCount` mechanism) would fail this case.
- Given `"!"` and `"A"`, `compareCodeUnits` returns `-1`.
- `test/collections.test.ts` runs green with the added cases, and the file's existing `rankCountEntries`/`sortByValueDesc`/`topAndHidden` cases pass unchanged (the pin is an addition; it changes no source behavior).
