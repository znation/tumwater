### TUI Pending overlaps: the Pending pane lists the files two or more roles' pending changes touch below the change roster, the terminal twin of `tumwater diff --overlaps` and the dashboard's Overlapping files card (planned 2026-10-20 by the plan role; independent of every eligible plan. "TUI transcript search" also edits src/ui/tui/tui-keys.ts (its `createTuiPanes` call) and test/tui-keys.test.ts, so whichever lands second rebases. Touches src/ui/tui/tui-keys.ts + src/ui/tui/tui-pane-session.ts + src/ui/tui/tui-pane-pending.ts + docs/how-it-works.md + docs/cli.md + docs/invariants.md + test/tui-keys.test.ts)

**Goal.** `tumwater diff --overlaps` and the dashboard's Pending "Overlapping files" card (PLANS-DONE.md "Pending overlaps in the dashboard") both list each file that two or more roles' pending changes touch. Both read `collectChangeOverlaps` (src/change/change-data.ts). The TUI's Pending pane (`createPendingPane`, src/ui/tui/tui-pane-pending.ts) paints only the merge queue and `renderTeamChange`'s roster. An operator in the terminal cannot see which roles are about to conflict. When planned, `grep -rn 'collectOverlaps\|pendingOverlapsText' src test` printed nothing.

**Approach.**
1. src/ui/tui/tui-keys.ts: add an optional seam `collectOverlaps?(root: string): Promise<ChangeOverlapsView>` to `TuiKeysDeps`, beside `collectPending`. Give it a doc comment in the same style: production uses change-data's `collectChangeOverlaps`, and tests inject it so they need no git plumbing. In `createTuiKeys`, add `const collectOverlaps = deps.collectOverlaps ?? collectChangeOverlaps;` and pass `collectOverlaps` in the `createTuiPanes({...})` object. Extend the existing change-data import with `collectChangeOverlaps` and `type ChangeOverlapsView`.
2. src/ui/tui/tui-pane-session.ts: add `collectOverlaps(root: string): Promise<ChangeOverlapsView>;` after `collectPending` in both `TuiPanesDeps` and `TuiPaneSession`. Add `collectOverlaps: deps.collectOverlaps,` to `createTuiPaneSession`'s returned object. Update `TuiPanesDeps`' doc comment from "the four async collectors" to "the five async collectors". Extend the type import from change-data.js.
3. src/ui/tui/tui-pane-pending.ts:
   - Add an exported pure `pendingOverlapsText(view: ChangeOverlapsView): string`. When `view.state === "no-base"` it returns `""`, because the roster above already says the main branch is missing. When `view.overlaps.length === 0` it returns `renderChangeOverlaps(view)` ("no file is touched by two pending changes"). Otherwise it returns `` `overlapping files (${view.overlaps.length}):\n` + renderChangeOverlaps(view) ``. The heading has the same shape as the queue's "merge queue (N):" heading. Import `renderChangeOverlaps` from "../../change/change-render.js" beside `renderTeamChange`.
   - In `refresh`, replace `session.collectPending(session.root).then(...)` with `Promise.all([session.collectPending(session.root), session.collectOverlaps(session.root)]).then(([team, overlaps]) => ...)`. Keep both guards (`gen !== refreshGen`, `session.view !== session.roleIds.length + 5`) unchanged. On success, set `const block = pendingOverlapsText(overlaps);` and `session.paneCache = queueText + "\n\n" + renderTeamChange(team) + (block ? "\n\n" + block : "");`. Leave the rejection arm as it is: either collector failing flashes the error and keeps the queue visible.
   - Extend the leading comment: the overlaps are read by the same `collectChangeOverlaps` that `tumwater diff --overlaps` and `GET /api/diff?overlaps=1` serve, and rendered through the CLI's `renderChangeOverlaps`.
4. docs/how-it-works.md: in the sentence that opens "The Pending pane shows the durable merge queue above the pending-change roster", add after that sentence: "Below the roster it lists the files two or more roles' pending changes touch, through the same `collectChangeOverlaps`/`renderChangeOverlaps` pair `tumwater diff --overlaps` prints."
5. docs/cli.md, the `Ctrl+R` row of the TUI keys table: change "refresh the merge queue and change roster on Pending" to "refresh the merge queue, change roster and overlapping files on Pending".
6. docs/invariants.md, section "Role change view: every known role answers, degraded rather than failing, with a bounded patch": change "`tumwater diff --overlaps` and the dashboard's `GET /api/diff?overlaps=1` list files" to "`tumwater diff --overlaps`, the dashboard's `GET /api/diff?overlaps=1` and the TUI's Pending pane list files".

**Acceptance criteria** (all in test/tui-keys.test.ts):
- Each of the five existing tests that pass `collectPending:` to `createTuiKeys` also passes `collectOverlaps: () => Promise.resolve({ mainBranch: "main", state: "no-base" as const, overlaps: [] })`. Each `await pending;` or `await Promise.resolve(); await Promise.resolve();` pair before a `paneCache` assertion becomes `await new Promise((r) => setImmediate(r));`, the flush the file already uses, because `Promise.all` adds microtask hops. Their expected `paneCache` strings stay as they are, since a no-base view adds no block.
- New test "the Pending pane lists overlapping files below the roster, through the CLI's renderChangeOverlaps". It injects `collectPending` resolving to `{ mainBranch: "main", roles: [{ role: "feature", branch: "tumwater/feature", state: "ready", ahead: 1, behind: 0, commits: [], dirtyFiles: [] }] }` and `collectOverlaps` resolving to `{ mainBranch: "main", state: "ready", overlaps: [{ path: "src/a.ts", roles: ["feature", "feature-2"] }] }`. After cycling to Pending (5× Ctrl+T after `syncSnapshot(0, false, [], false)`) and flushing with `setImmediate`, `paneCache` equals `"merge queue empty\n\nfeature: 1 commit ahead of main\n\noverlapping files (1):\nsrc/a.ts: feature, feature-2"`.
- New test "pendingOverlapsText states an empty overlap list and omits a no-base one". It imports `pendingOverlapsText` from "../src/ui/tui/tui-pane-pending.js". `{ mainBranch: "main", state: "ready", overlaps: [] }` → `"no file is touched by two pending changes"`. `{ mainBranch: "trunk", state: "no-base", overlaps: [] }` → `""`.
- New test "a rejecting overlaps collector keeps the Pending queue and flashes the error". `collectOverlaps: () => Promise.reject(new Error("boom"))` with a resolving `collectPending`. After the flush, `paneCache` equals `"merge queue empty"`, and `keys.state().flash` equals "error: boom" (the test's `now: () => 0` keeps the flash unexpired).
- `npm run test:gate` passes.
