### `validEntries`'s keep-passing / drop-foreign / `__proto__`-stays-an-own-property rule is pinned in test/json-object.test.ts, so a regression in the one home of the map-level untrusted-JSON read the untrusted-JSON family shares is caught by the suite (planned 2026-11-15 by the plan role; `validEntries(value, guard)` in src/files/json-object.ts is the shared "keep only the well-formed entries of an untrusted map, drop the foreign ones" read its two call sites apply — the per-pair daily spend map's heal (src/runner/runner-state-load.ts `healPairCosts`) and the opencode catalog cache's models map (src/agent/opencode/opencode-catalog.ts). Its sibling single-value reads — `isJsonObject`/`objectOrEmpty`, `parseJsonObject`, `stringList`, `finiteNumber`, `nonNegativeNumber` — are already pinned in test/json-object.test.ts through the INV-AF1/AF3 guarantees (docs/invariants.md "Untrusted JSON" section), but the map-level half of the family — `validEntries` (read) and `setOwn` (write), which have no single-value twin — is not; this plan pins the read half, `validEntries` (`setOwn`'s write half, the `Object.defineProperty` `__proto__`-safe store, is a separate entry). `validEntries` is untested — `grep -rn --include='*.test.ts' validEntries test/` matches nothing, and the call-site tests (test/opencode-catalog.test.ts, the runner-state-load loading tests) pin only the happy path, none drive a torn or foreign map at the guard. **Goal.** Pin the one unpinned member of the untrusted-JSON read family in src/files/json-object.ts. `validEntries(value, guard)` is the single home of the rule that decides which entries of an untrusted map survive a heal or load: keep the entries that pass the caller's `guard`, drop the foreign ones, and — because it rebuilds with `Object.fromEntries` — keep a `__proto__` key as an own property instead of a bare index-assignment reaching into `Object.prototype`. Every map-typed read of a persisted or wire value that runs through it (the per-pair daily spend map's heal, the opencode catalog's models map) is exposed to that same rule, so a regression that would keep a poison entry or corrupt the prototype is the class of bug a corrupt-cache reader can carry into a budget comparison or a catalog model. Pin its three behaviors with plain `assert` in the existing test file.

**Approach.** One file, test-only, no src change and no invariant edit: add tests to the existing test/json-object.test.ts (which already imports from `../src/files/json-object.js`) importing `validEntries` (and `nonNegativeNumber` for the number-guard case). Drive each branch in isolation. No repo, worktree, fs, git, or clock. The `__proto__` input must be built with `JSON.parse` — an object literal `{"__proto__": x}` triggers the assignment trap at creation and does not model what the callers actually receive (a value read back from disk via `readJsonFile`, i.e. `JSON.parse`).

**Files touched.** test/json-object.test.ts (new `validEntries` cases only).

**Acceptance criteria.**
- Given a non-object `value` — a scalar `5`, `null`, or an array `[1,2,3]` — `validEntries(…, anyGuard)` returns `{}` (the map is not an object, so there is nothing to keep). The guard is never the reason; the shape is.
- Given an object whose entries all pass a number guard — `validEntries({ a: 1, b: 2 }, (v): v is number => nonNegativeNumber(v, -1) >= 0)` — the result is `{ a: 1, b: 2 }` (every passing entry kept, in source order).
- Given a mixed object — `validEntries({ a: 1, b: { x: 1 }, c: "s" }, (v): v is number => nonNegativeNumber(v, -1) >= 0)` — the result is `{ a: 1 }`: the object entry `b` and the string entry `c` are dropped for failing the guard, the number `a` survives. (The same rule under an object-valued guard keeps the object entry instead, so the drop is the guard's call, not `validEntries`'s.)
- Given a map whose value is a JSON `__proto__` key — the input `JSON.parse('{"__proto__":7,"a":1}')` under a guard that keeps numbers — the result exposes `__proto__` as an own property: `Object.keys(result)` is `["__proto__","a"]`, `result["__proto__"]` is `7` (not `Object.prototype`), `result.a` is `1`, and `Object.prototype` is left untouched — `Object.prototype.a` stays `undefined`.
- Given an empty object, `validEntries({}, guard)` returns `{}`.
- Every pre-existing test passes unmodified; no source file, no other test file, and no docs file change; the project's declared check is green.
