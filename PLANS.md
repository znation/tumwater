**Goal.** The `ReportDay` map-cell key should type-check on the *read* side of the report, not just the write side: a renamed or added `ReportDay` map cell is a compile error at `rankedBy`'s call sites, the same guarantee `ade90439` gave the collector's `setMapIfNonempty`. The cast is the one thing standing between `rankedBy` and that guarantee. Behavior is preserved: the `?? {}` zero-means-absent guard is untouched, so a day with no entry of a kind still ranks to `"-"` and the report renders byte-identically.

**Approach.**
- In src/report/report-data.ts: change `type DayMapKey =` to `export type DayMapKey =` (keep the doc comment; it is a type alias, so this adds no value to the module's export surface and no new import dependency — report-data.ts already imports `ReportDay` from report-types.ts, which the alias derives from).
- In src/report/report-render.ts: add `import type { DayMapKey } from "./report-data.js";`; change `rankedBy`'s signature from `function rankedBy<K extends keyof ReportDay>(series: ReportDay[], field: K): [string, number][]` to `function rankedBy(series: ReportDay[], field: DayMapKey): [string, number][]`; and drop the cast in its body — `(d[field] as Record<string, number> | undefined) ?? {}` becomes `(d[field] ?? {})` (for a `DayMapKey` key, `d[field]` is already `Record<string, number> | undefined`, so `?? {}` type-checks to `Record<string, number>`, the type `rankedRoleTotals`'s `pick` parameter expects — no cast needed). `rankedBy` is module-private, so no other file references it; the `rankedBy` doc comment is otherwise left as-is.
- No `ReportDay` field is added, renamed, or re-typed; the `?? {}` guard and every other line in both files are untouched.

**Files touched.** src/report/report-data.ts, src/report/report-render.ts
