### Run transcript search in the dashboard: the History drill-down's open transcript gets a search box that narrows it through `GET /api/run?…&transcript=1&grep=`, the twin of `tumwater history <role> <n> --transcript --grep` (planned 2026-10-20 by the plan role; independent of every eligible plan. "TUI Pending overlaps" also edits the docs/how-it-works.md sentence that directly follows this plan's insertion point, so whichever lands second rebases. Touches src/gui/gui-endpoints.ts + src/ui/gui/gui-client-history.ts + docs/how-it-works.md + test/gui-server-api.test.ts + test/gui-client-history.test.ts)

**Goal.** `tumwater history <role> <n> --transcript --grep <text>` (PLANS-DONE.md "Run transcript search") narrows one past run's transcript to the entries that contain the text. `runTranscriptLines` (src/run/run-detail.ts) already takes a raw `grep` and lowercases it itself. It also words the miss note `(no transcript entries matching "<text>" in <role> run <n>)`. The dashboard's History drill-down cannot do this. Its Show transcript button (`toggleHistTranscript`, src/ui/gui/gui-client-history.ts) fetches `GET /api/run?…&transcript=1`, and `handleRun`'s `transcriptText` helper (src/gui/gui-endpoints.ts) passes only `{ includePrompts }`. When this was planned, `grep -rn 'histTranscriptGrep\|data-hist-transcript-grep' src test` printed nothing.

Behavior, decided:
- The box appears only while the transcript is open (`t.state === "ok" && t.open`), right after the Show prompts button. It is markup inside the card, and `renderHistory` rewrites `histbody`'s innerHTML on every state change. So it applies on the `change` event (Enter or blur), the same event the toolbar's `histgrep` box uses, never on `input`. Each render paints the applied pattern back as the box's escaped `value`.
- An applied pattern is stored on the card's transcript sub-state as `t.grep`. The filtered text is fetched with `&grep=` plus `&prompt=1` when `t.prompts` is on, and shown in place of the plain or prompt text. An empty or blank value clears the search without a fetch.
- Toggling Show/Hide prompts clears the search (`delete t.grep`, `t.grepText`, `t.grepLoading`, `t.grepError`), so the two modes never disagree about which text is shown. Hide/Show transcript keeps it. `fetchHistory` already clears `histDetails`, so a refetch drops it with the card.
- The match is case-insensitive, and the server does the matching through `runTranscriptLines`. The client never filters.

**Approach.**
1. src/gui/gui-endpoints.ts: `transcriptText` gains a `grep: string | undefined` parameter, which it passes as `runTranscriptLines(root, role, run, detail, { includePrompts, grep })`. In `handleRun`, read `const grep = (q.get("grep") ?? "").trim();` and pass `grep === "" ? undefined : grep`. Do not lowercase it, because `runTranscriptLines` lowercases it and quotes the raw text in its miss note. Extend `handleRun`'s doc comment: "a non-blank `grep` (with `transcript`) keeps only the entries containing the text, case-insensitively, each under its agent run's separator, the text `history --transcript --grep` prints, or its miss note". `grep` without `transcript` adds nothing, as `prompt` without it does today.
2. src/ui/gui/gui-client-history.ts, inside the `history-detail:start`/`end` region so `HISTORY_REGIONS` tests reach it:
   - `histTranscriptHtml`: in the `t.state === "ok" && t.open` branch, after the prompts button, add `" <input type='search' class='field' data-hist-transcript-grep='" + esc(key) + "' placeholder='Search transcript' aria-label='Search transcript' autocomplete='off' value='" + esc(t.grep || "") + "'>"`. Next to the prompts loading and error spans, add `if (t.grepLoading) out += " <span class='muted'>Searching transcript…</span>";` and `if (t.grepError) out += "<div class='err'>" + esc(t.grepError) + "</div>";`. The `<pre>` body becomes `esc(t.grep && typeof t.grepText === "string" ? t.grepText : t.prompts ? t.promptText : t.text)`.
   - New `async function searchHistTranscript(key, value)`: get `entry`, return unless `entry.state === "ok"`. Get `t = entry.transcript` and return unless `t && t.state === "ok" && t.open`. `const grep = String(value ?? "").trim();`. When `grep === ""`, delete `t.grep`, `t.grepText`, `t.grepLoading` and `t.grepError`, call `renderHistory()`, and return. Otherwise set `t.grep = grep; t.grepLoading = true;`, delete `t.grepText` and `t.grepError`, and call `renderHistory()`. Fetch `"/api/run?role=" + encodeURIComponent(key.slice(0, at)) + "&run=" + encodeURIComponent(key.slice(at + 1)) + "&transcript=1" + (t.prompts ? "&prompt=1" : "") + "&grep=" + encodeURIComponent(grep)`, with `at = key.lastIndexOf("#")` as the sibling toggles use. On the answer, return without touching anything when `entry.transcript !== t || t.grep !== grep`, because a newer search or a prompts toggle superseded it. Throw `new Error("/api/run answered without a transcript field")` when `typeof d.transcript !== "string"`, else set `t.grepText = d.transcript`. In the catch, set `t.grepError = err && err.message ? err.message : "the search failed"`, with the same staleness guard. Then `delete t.grepLoading` and call `renderHistory()`.
   - `toggleHistTranscriptPrompts`: right after its guard line (`if (!t || t.state !== "ok" || !t.open || t.promptsLoading) return;`), delete `t.grep`, `t.grepText`, `t.grepLoading` and `t.grepError`.
   - Beside the "Show prompts" click listener in the view's setup, register `$("histbody").addEventListener("change", (ev) => { const el = ev.target instanceof Element ? ev.target.closest("input[data-hist-transcript-grep]") : null; if (el) searchHistTranscript(el.dataset.histTranscriptGrep, el.value); });`, with the comment `// The open transcript's search box (applied on Enter or blur: the card re-renders on every change).`
   - Extend the `histDetails` state comment's transcript clause with `{ grep?, grepText?, grepLoading?, grepError? }` for the search box, which shows the server-filtered text while set and is cleared by the prompts toggle.
3. docs/how-it-works.md: after the "Once it is open, a "Show prompts" button reloads it through `GET /api/run?…&transcript=1&prompt=1` …" sentence, add: "Its search box (applied on Enter) reloads it through `GET /api/run?…&transcript=1&grep=<text>`, keeping only the entries containing the text, the text `tumwater history <role> <n> --transcript --grep` prints; toggling prompts clears it."

**Files.** The five listed in the heading. `grep -n 'api/run' docs/invariants.md` printed nothing when planned, so the plan claims no invariant ID.
