### Refusal: a failed PLANS.md strip write keeps the refusal going (its other notes still merge) instead of throwing out of handleRefusal (planned 2026-10-20 by the plan role; independent of every eligible plan; touches src/verdict/refusal.ts + test/refusal.test.ts + docs/invariants.md)

**Goal.** `handleRefusal` (src/verdict/refusal.ts) documents "Never throws". Before it gathers the notes to commit, it strips the Refused note from any plan that is still blocked by a planned prerequisite (`withoutBlockedPlanRefusals`). That strip ends in `writeTextAtomic(plansFile, md)`, and the write has no `try`. If the write throws (full disk, EACCES), the error escapes `handleRefusal` and its caller in src/run/run-verdict.ts. Nothing is committed, and every other note the run wrote goes unmerged with it, such as a BUGS.md Refused note. A scratch test on 2026-10-20 reproduced this. Main's PLANS.md held "S, part 1/2" and "S, part 2/2" (the second requires part 1/2). The worktree added a Refused note under part 2/2 and a Refused note under a BUGS.md entry. With every `.tmp-` `writeFileSync` faulted to throw ENOSPC, `handleRefusal` threw `Error: ENOSPC`. No merge was called, and `git status` showed ` M BUGS.md` and ` M PLANS.md`. The strip is a cleanup step, so its failure should not cost the refusal. Committing PLANS.md unstripped would merge the very note the strip exists to drop, so PLANS.md must stay out of the commit instead. A plan refusal skipped this way is not lost for good: the entry stays unrefused on main, and the next run that takes it can refuse it again.

**Approach.** src/verdict/refusal.ts, `handleRefusal`:
1. Declare `let plansUnstripped = false;` before the `if (fs.existsSync(plansFile))` block. Wrap the `writeTextAtomic(plansFile, md);` call in `try { … } catch (err) { … }`. In the catch, set `plansUnstripped = true` and log one warning with `logEventBestEffort(ctx.root, { source: ctx.role, type: "warning", message })`. The message is `could not drop refusal note(s) on blocked plan(s) ${dropped.map((t) => `"${t}"`).join(", ")}: ${errorMessage}; PLANS.md is left out of this refusal's commit`. To build `errorMessage`, use the error-to-string helper the file or its neighbours already use (grep `src/` for an existing one such as `errorMessage` before writing; otherwise use `err instanceof Error ? err.message : String(err)`). The per-title "dropped refusal note" warnings in the loop after the write must run only when the write succeeded, so put them inside the `try` after the write.
2. Where `notes` is computed (`(await changedFiles(wt)).filter(...)`), also filter out `"PLANS.md"` when `plansUnstripped` is true. `commitPathsAndDiscardRest` then commits the remaining notes and discards PLANS.md with `reset --hard HEAD`. When PLANS.md was the only note, `notes` is empty and the existing `if (!commit)` branch resets the worktree and returns `{ result: "refused", summary: reason }`. The `newlyRefusedTitles` loop already skips files missing from `notes`, so `entry_refused` names no plan.
3. Add one sentence to `handleRefusal`'s doc comment: a failed write of the stripped PLANS.md logs a warning and leaves PLANS.md out of the commit, so the other notes still merge.

**Files touched.** src/verdict/refusal.ts (`handleRefusal`), test/refusal.test.ts, docs/invariants.md.
