A post-merge rejection is a different event from a pre-merge one: the commit already merged, so the rejection names it to the revert path off main (src/baseline/main-revert.ts's `MainCulprit.postReview`). The usage report folds every `review_rejected` into one `rejectionsByRole` map (src/report/report-fold.ts), so an operator reading `tumwater report` cannot tell how many of a role's rejections were returned after the change had already landed — the costly kind. Add that subset as its own ranked line, so the report shows the rejections that escaped to main beside the ones the gate caught.

**Approach.**
- src/report/report-fold.ts: `UsageFold` and `DayFold` each gain `postMergeRejectionsByRole: Record<string, number>` beside `rejectionsByRole`, documented as the `review_rejected` events whose `afterMerge` is true, per role id — a subset of `rejectionsByRole`, kept apart because a post-merge rejection turns back an already-merged commit. In `foldUsageEvent`'s `review_rejected` branch, after `addTo(target.rejectionsByRole, eventRole(ev), 1);` add `if (ev.afterMerge === true) addTo(target.postMergeRejectionsByRole, eventRole(ev), 1);`. `dayFoldFor` initialises it to `{}`.
- src/report/report-data.ts: `collectReportSince`'s `acc: UsageFold` literal gains `postMergeRejectionsByRole: {}`, and its returned object gains `postMergeRejectionsByRole: scopedByRole(acc.postMergeRejectionsByRole, bases),` beside `rejectionsByRole`. `collectReport`'s team branch sets `day.postMergeRejectionsByRole = fold.postMergeRejectionsByRole` only when non-empty (the zero-means-absent rule its siblings use); its scoped branch narrows with `narrowToRole(fold.postMergeRejectionsByRole, bases)` and sets it only when non-empty.
- src/report/report-types.ts: `ReportDay` gains optional `postMergeRejectionsByRole?: Record<string, number>`; `SinceReport` gains required `postMergeRejectionsByRole: Record<string, number>` (always present, empty when none). Both doc comments say it is the `afterMerge: true` subset of that interface's `rejectionsByRole`.
- src/report/report-render.ts: in `renderSinceReportMarkdown`, after `pushRankedRoleLine(lines, "Rejections by role", rankedRoleMap(data.rejectionsByRole));` add `pushRankedRoleLine(lines, "Post-merge rejections by role", rankedRoleMap(data.postMergeRejectionsByRole));`. In `renderReportMarkdown`, after its `Rejections by role` push add `pushRankedRoleLine(lines, "Post-merge rejections by role", rankedRoleTotals(data.series, (d) => d.postMergeRejectionsByRole ?? {}));`. Update both surrounding comments to say the new line is the `afterMerge: true` subset.
- docs/cli.md, the `tumwater report` row's ranked per-role list: after "rejections (from `review_rejected` events)" add "post-merge rejections (those `review_rejected` events that carried `afterMerge: true` — a merged commit the reviewer turned back, so it had to be reverted off main)".
