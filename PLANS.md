### `isPlainDecimal`'s plain-decimal-literal rule and `isExponentSpelling`'s exponent rule are pinned in test/text.test.ts, so a regression in the one home of the decimal-literal shape rule — the rule every numeric-write surface (the config writer, the TUI budget/interval/instances/team-key editors, the CLI role writes) applies to admit only a literal a user typed, and to refuse the `1e2`/`0x10` spellings `Number()` would silently read as numbers — is caught by the suite (planned 2026-11-15 by the plan role; `isPlainDecimal(raw: string): boolean` and `isExponentSpelling(raw: string): boolean` in src/text/text.ts are the two halves of the numeric-literal shape rule the numeric-write surfaces read through: `isPlainDecimal` is a single regex `^\d*\.?\d+$` (a run of digits with an optional fractional part, at least one digit — `25`, `12.34`, `.5`, `300`) and `isExponentSpelling` is its complement-shaped guard `!isPlainDecimal(raw) && /^\d+(\.\d+)?[eE][+-]?\d+$/.test(raw)` (an exponent spelling `1e2`, `2.5E-3`, `4e1` that `Number()` would read as a real number `100`/`0.0025`/`40`, and `JSON.parse` would read past an integer validator); `isExponentSpelling` is called from four surfaces (src/config/config-write.ts, src/cli/cli-role-command.ts in three places, and the TUI per-role instances + team-key editors in src/ui/tui), `isPlainDecimal` from three (src/cli/cli-role-command.ts's `plainDecimalToJson`, and the TUI budget/interval editors in src/ui/tui); independent of the other `## Planned` entry, which pins a different exported function in a different src module (src/cli/cli-args.ts) through a different test file (test/cli-args.test.ts) — this one pins src/text/text.ts through test/text.test.ts, and the two share no src module, test file, or named import — so feature may take either)

**Goal.** `isPlainDecimal` and `isExponentSpelling` (src/text/text.ts, both exported) are the one home of the decimal-literal shape rule every numeric-write surface reads through: a literal the operator typed must be a plain decimal (`25`, `12.34`, `.5`, `300`) to be admitted, and an exponent spelling (`1e2`) must be refused rather than let `Number()`/`JSON.parse` read it as a number. Each is a pure `string → boolean` read with no `fail`, no git, fs, shell or clock, yet no test drives either directly — only their callers' tests reach them, and none pins the shape rule's own accept/refuse boundary. Pin both predicates through their exported functions.

**Approach.** One file, test-only, no src change and no invariant edit (INV-AD4 already pins the *integer* rule on `parsePositiveInt`/`parseNonNegativeInt`; the *decimal-literal* rule these two predicates own admits a fractional part and is a distinct, unpinned pair, so docs/invariants.md needs no change): in test/text.test.ts add `isPlainDecimal` and `isExponentSpelling` to the existing named-import block from `../src/text/text.js`, then pin each branch with plain `assert.equal` against the booleans they actually return. Each case is a single assert, no repo, worktree, fs, git or clock. `isPlainDecimal` true cases: `25`, `12.34`, `.5`, `300`, `0`, `0.5`. `isPlainDecimal` false cases: `1.` (a dot with no following digit), `""` (empty), `1e2` (exponent), `0x10` (hex), `-5` and `+5` (signs), `" 5"` and `"5 "` (whitespace), `1.2.3` (two dots), `"1 2"` (inner space). `isExponentSpelling` true cases: `1e2`, `2.5E-3`, `4e1`, `1E+10`, `1e+3`, `0e0`, `1E0`, `1.0e1`. `isExponentSpelling` false cases: `3e` (no exponent digits), `e5` and `1e` (no mantissa / no exponent digits), `1e+` and `1e-` (sign with no digits), `1.5e2.3` (fractional exponent part), `1e2x` and `" 1e2"` and `"1e2 "` (trailing junk / edge whitespace), and `25` (a plain decimal, refused by the `!isPlainDecimal` gate so the two shapes stay mutually exclusive). No source file and no other test file change.

**Files touched.** test/text.test.ts.

**Acceptance criteria.**
- Given a plain decimal with integer digits only, `isPlainDecimal("25")` is `true` and `isPlainDecimal("300")` is `true`.
- Given a plain decimal with a fractional part, `isPlainDecimal("12.34")` is `true` and `isPlainDecimal("0.5")` is `true`; a leading-dot fractional `isPlainDecimal(".5")` is `true`.
- Given `0` and `0.5`, `isPlainDecimal("0")` is `true` and `isPlainDecimal("0.5")` is `true` — zero is a plain decimal (the integer rule is a separate concern pinned by INV-AD4).
- Given a dot with no following digit, `isPlainDecimal("1.")` is `false`; given an empty string, `isPlainDecimal("")` is `false`.
- Given a spelling `Number()` would read as a number but that is not a plain decimal, `isPlainDecimal("1e2")` is `false` (exponent) and `isPlainDecimal("0x10")` is `false` (hex) — the rule admits only the literal spelling the operator typed.
- Given a sign or whitespace, `isPlainDecimal("-5")` is `false`, `isPlainDecimal("+5")` is `false`, `isPlainDecimal(" 5")` is `false`, and `isPlainDecimal("5 ")` is `false`.
- Given more than one dot or an inner space, `isPlainDecimal("1.2.3")` is `false` and `isPlainDecimal("1 2")` is `false`.
- Given an exponent spelling, `isExponentSpelling("1e2")` is `true`, `isExponentSpelling("2.5E-3")` is `true`, `isExponentSpelling("4e1")` is `true`, `isExponentSpelling("1E+10")` is `true`, and `isExponentSpelling("1e+3")` is `true` — `Number()` would read each as a real number, which is why every numeric-write surface refuses it.
- Given a degenerate exponent shape, `isExponentSpelling("3e")` is `false` (no exponent digits), `isExponentSpelling("e5")` is `false` and `isExponentSpelling("1e")` is `false` (missing mantissa or exponent digits), and `isExponentSpelling("1e+")` and `isExponentSpelling("1e-")` are `false` (a sign with no following digit).
- Given a fractional or trailing-junk exponent part, `isExponentSpelling("1.5e2.3")` is `false`, `isExponentSpelling("1e2x")` is `false`, `isExponentSpelling(" 1e2")` is `false`, and `isExponentSpelling("1e2 ")` is `false` — the exponent must fill the whole string.
- Given a plain decimal (no `e`), `isExponentSpelling("25")` is `false` — the `!isPlainDecimal` gate keeps the two shapes mutually exclusive, so a plain decimal is never misread as an exponent.
- Every pre-existing test in test/text.test.ts passes unmodified; no source file and no other test file change; the project's declared check is green.
