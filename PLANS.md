### Merge write-back: a failed role-state save in `writeMergeOutcome` warns and still drops the settled queue entry, instead of leaving a merged change queued for a second review (planned 2026-10-20 by the plan role; independent of every eligible plan; touches src/merge/merge-slot.ts + test/merge-slot.test.ts + docs/invariants.md)

**Goal.** `writeMergeOutcome` (src/merge/merge-slot.ts) runs after a merge has settled, often after the change is already on main. Its order is `applyMergeOutcome`, then `saveRunnerState(root, state)` with no guard, then the streak warning, the best-effort `merge_done`/`merge_failed` event, and finally `dropMerge(file)`. Its doc comment says an unwritable feed "must not skip the drop, or the settled entry would stay queued and be re-verified and re-merged on the next drain". A failed state save skips the drop in exactly that way. The throw also skips the rest of `settleMergeOutcome` (src/merge/merge-pipeline.ts): `removeMergeChange` and `requeueKeptChange` never run. `guardMergeTask` catches it and logs "merge task for <role> could not settle". On 2026-10-20 the plan role confirmed this with a scratch test (since deleted) in a copy of test/merge-slot.test.ts. It queued an entry with the file's `queued(root)` helper, installed `failRenameSyncOn(statePath(root, "improve"), "EACCES fake")`, and called `writeMergeOutcome(root, entry, state, "changed", 7, { tokens: 0, cost: 0, providerCost: {} }, file)`. The call threw `Error: EACCES fake`, `queueDepth(root)` was 1, the queue file still existed, and the log held no events. The live `state` object is the runner's own state, so the outcome is already applied in memory, and the runner's next save writes it to disk.

**Approach.**
1. src/merge/merge-slot.ts, `writeMergeOutcome`: replace `saveRunnerState(root, state)` with `saveRunnerStateBestEffort(root, state)`. It is already imported, and on failure it warns under the role's id with "could not save the role's state: <message>". Add one sentence to the doc comment: a failed state save warns and does not skip the drop either, because the in-memory state already holds the outcome and the runner's next save writes it. Leave `saveRunnerState` in `requeueKeptChange` alone (its caller `settleMergeOutcome` already wraps it in a `try`). Leave merge-core.ts alone (its verdict save runs before the merge, not after a durable step). Keep the `saveRunnerState` import only while some other call in the file still uses it (`grep -n 'saveRunnerState(' src/merge/merge-slot.ts`).
2. test/merge-slot.test.ts: after "an unwritable events feed still drops the settled entry — the queue never retries", add "a failed role-state save still logs the outcome and drops the settled entry". Use `queued(root)` and `freshRunnerState("improve")`. Install `failRenameSyncOn(statePath(root, "improve"), "EACCES fake")` (add `failRenameSyncOn` to the existing ./helpers/fs-faults.js import and `statePath` to the ../src/paths.js import), call `writeMergeOutcome(root, entry, state, "changed", 7, { tokens: 0, cost: 0, providerCost: {} }, file)`, and undo the fault in a `finally`. Assert that `queueDepth(root)` is 0, that `fs.existsSync(file)` is false, that `state.commits` is 1 (the in-memory fold), that `readEvents(root, 10)` has one `merge_done` event, and that `warningMessages(root)` (from ./fixtures/log-fixtures.js) is exactly one entry matching `/could not save the role's state: EACCES fake/`.
3. docs/invariants.md: append "## Merge write-back: a settled entry is always dropped" after the last section, using the Guarantee / Binds / Pinned by layout. For the prefix, run `grep -n '^### INV-' docs/invariants.md | tail` and read the "was free" notes in PLANS.md's Planned entries. On 2026-10-20, BU had merged, BV (OpenCode catalog cache) and BW (QA flow coverage) were planned, and BX was free. Write one guarantee: `writeMergeOutcome` drops the entry's queue file for every result, even when the role's state save or the event write fails; each failure warns and nothing throws. Binds `writeMergeOutcome` and `saveRunnerStateBestEffort`. Pinned by the new test plus "an unwritable events feed still drops the settled entry — the queue never retries" and "a merge's nonzero usage rides its merge_done event and the entry is dropped". Cite each test by its full name.

**Acceptance criteria.**
- With step 1 reverted (back to `saveRunnerState`), the new test fails because the call throws `EACCES fake`.
- `npm run test:gate` passes.
- `git diff --stat` shows src/merge/merge-slot.ts as the only changed src/ file.
- Each test name cited in the new section exists verbatim (`grep -rF` each one in test/).
