**Goal.** The landed `tumwater reviews --accept <n>` (src/review/post-review-accept.ts, `acceptPostReview`) is the at-risk alert's "accept the commit unreviewed deliberately" action, and the dashboard Pending card is getting its two-click Accept twin. The TUI Pending pane already paints the same post-merge review queue (`readPostReviews`/`renderPostReviews`), but its rows are not selectable and it offers only the merge-queue actions Ctrl+X (cancel) and Ctrl+V (top), so a terminal operator reading the TUI's attention alert must leave the pane and run the CLI. Make the review rows selectable in the pane's one row selection and add the accept action, reusing the landed position-based `acceptPostReview` exactly as the merge arms reuse `cancelQueuedMerge`.

**Approach.**
- src/ui/tui/tui-pane-pending.ts: define `type PendingRow = { kind: "merge"; entry: MergeEntry; position: number } | { kind: "review"; entry: PostReview; position: number };` and make the pane's cached list `queueRows: PendingRow[]` (the name and the `state()` shape `{ selectedQueue, queueDetail }` stay, so `test/tui-keys.test.ts`'s merge assertions are unchanged). In `rebuildQueueRows`, after building the merge rows (whole queue or Ctrl+G-scoped), append `lastReviews.map((entry, i) => ({ kind: "review", entry, position: i + 1 }))`: the review block `reviewsHead` is never role-scoped, so a review row's position is its 1-based whole-list position, the one `tumwater reviews --accept <n>` takes.
- Replace `mergeDetail` with `rowDetail(row: PendingRow)`: a merge row returns today's `merge #N (Ctrl+X to cancel, Ctrl+V to top): …` text unchanged; a review row returns `` `review #${row.position} (Ctrl+A to accept): ${roleLabel(entry.role)} ${shortSha(entry.commit)} · ${squash(entry.summary, 80)}` `` plus ` · ${postReviewStatusLabel(entry)}` when that label is non-empty, and for an entry with `rejected` a second line saying it cannot be accepted until its revert runs. Import `postReviewStatusLabel` from `../../review/post-review-render.js` (its `lastFailure` suffix, added by the in-flight last-failure plan, reaches the TUI for free) and `squash` from `../../text/text.js`.
- `selectedQueueRow()` becomes `selectedRow()` returning the selected `PendingRow` or null; keep the exact `select a merge with ↑↓ first` flash for the null case (the existing test pins it). The Ctrl+X and Ctrl+V arms call it and, when the row is a review, flash `that row is a post-merge review — Ctrl+A accepts it` and return true; the merge arms and all their wording are unchanged.
- Add a Ctrl+A arm beside Ctrl+V, guarded `key.ctrl && key.name === "a" && promptLineFree(ctx.es) && session.view === session.roleIds.length + 5`. It needs a selected review row; on a merge row it flashes `that row is a queued merge — Ctrl+X cancels it` and returns true. This mirrors the Ctrl+X cancel arm's re-read guard and `refresh()`, and is the pane's second two-step arm.
