### `tumwater history --last` with no role opens the newest completed run of any role, and `--result`/`--model` narrow it the same way (planned 2026-10-20 by the plan role; independent of every eligible plan: none of them touch src/run/run-detail.ts, src/cli/cli-command-args.ts or the `runTrailCommand` in src/cli.ts — the `GET /api/history?result=` plan edits src/gui/gui-endpoints.ts, and this plan leaves that file's `newestRunNumber` call working unchanged)

**Goal.** `tumwater history <role> --last [--result <class>[,...]] [--model <selector>[,...]]` opens one role's newest run. The question an operator asks first after time away is "what just happened anywhere?", and today that takes `tumwater history -n 1` and then a second command with the role and number it printed. `tumwater history --last --result problems` should open the team's newest failure directly. It takes the same `--stat`, `--patch`, `--transcript` and `--json` flags as the role form.

**Approach.**
1. src/cli/cli-command-args.ts `historyTrailForm`: also return true when `args` contains `--last`. The listing form does not admit `--last` (its `rejectUnknownArgs` spec list in src/cli.ts's `history` case has no `LAST_FLAG`), so this only reroutes an invocation that fails today. Update the doc comment to name the bare `history --last` form.
2. src/cli.ts `runTrailCommand`: replace the `positionals.length < 1` arity check so that zero positionals pass only when `rest.includes("--last")`; with neither, it still fails with `usage: ${RUN_DETAIL_USAGE}`. `tumwater tick` with no args must still fail with that usage (the existing test that runs it outside a repo covers this).
3. src/run/run-detail.ts:
   - Add `export function newestRunRow(root: string, role: string | null, classes: HistoryResultClass[] | null, models: string[] | null): RunRow | null`. Move `newestRunNumber`'s body into it, return the row, and pass `role` straight to `readRunRows` (its `RoleScope` takes `null` for every role). `newestRunNumber` becomes `newestRunRow(root, role, classes, models)?.run ?? null` and keeps its signature, so `handleRun` in src/gui/gui-endpoints.ts does not change.
   - `runNotFoundLastMessage(role: string | null, …)`: when the role is `null`, pass `"any role"` to `runNotFoundPhrase`. The message then reads `no completed run with result "refused" for any role in the scanned window (the retained log may have rotated past it)`.
   - `cmdRunDetail`: when `last` is set and there are no positionals, resolve with `newestRunRow(root, null, classes, models)`, take `role` from `row.role` and the run number from `row.run`, then render exactly as the role form does. A miss prints `runNotFoundLastMessage(null, classes, models)` (or `null` under `--json`) at exit 0. Keep the role check and the arity error for one or two positionals as they are. Update the doc comment.
   - `RUN_DETAIL_USAGE` stays as it is, because test/run-detail.test.ts matches its text. The bare form is documented in the help prose instead.
4. src/cli/help.ts `history <role>` stanza: after "--last shows the role's newest finished run instead of numbering one;" add "with no <role>, --last shows the newest finished run of any role;". docs/cli.md "Watch run history" row: after "`tumwater history <role> --last` shows the newest completed run's trail instead of numbering one;" add "`tumwater history --last` with no role shows the newest completed run of any role (`history --last --result problems` opens the team's latest failure);".

**Files touched.** src/cli/cli-command-args.ts, src/cli.ts, src/run/run-detail.ts, src/cli/help.ts, docs/cli.md, test/run-detail.test.ts, test/cli-command-args.test.ts.

### Dashboard Pending view's Overlapping files card gets a Folder picker that keeps only the shared files at or under the chosen directory, each still naming every holder: the dashboard twin of `tumwater diff --overlaps --path <dir>` (planned 2026-10-20 by the plan role; independent of every eligible plan: no waiting plan touches src/ui/gui/gui-client-pending.ts, test/gui-client-pending.test.ts or docs/how-it-works.md. Touches src/ui/gui/gui-client-pending.ts test/gui-client-pending.test.ts docs/how-it-works.md)

**Goal.** `tumwater diff --overlaps --path <path>` and `GET /api/diff?overlaps=1&path=<path>` keep only the shared files at or under a path (`scopeChangeOverlapsToPath`, src/change/change-data.ts, through the private `inPath` rule). The dashboard's Overlapping files card (`pendingOverlapsHtml`, src/ui/gui/gui-client-pending.ts) only has the Role picker. An operator who owns one area cannot narrow the card to it. Add a Folder picker beside the Role picker. Its options are every directory that holds an overlapping file, so it needs no text input. A text input would also lose focus on every repaint, because `paintPendingOverlaps` replaces the card's `innerHTML`. Filtering stays client-side over the one `/api/diff?overlaps=1` document, as the Role picker does.

**Approach** (all in the `GUI_CLIENT_PENDING_JS` string, inside the `pending-table:start`/`pending-table:end` markers for the pure functions):
1. Add `function pendingOverlapDirs(view)`. It returns the sorted, de-duplicated directories of every overlap path. For each overlap whose `path` is a string, strip one trailing `/`, split on `/`, and add each proper prefix (`a`, `a/b` for `a/b/c.ts`). When the path ended in `/` (an untracked-directory entry such as `src/new/`), also add the stripped path itself (`src/new`). A malformed document (not an object, or `overlaps` not an array) returns `[]`, as `pendingOverlapHolders` does. A root-level file such as `README.md` adds nothing.
2. Add the module-level `let pendingOverlapDir = "";` beside `pendingOverlapRole`.
3. `pendingOverlapsHtml(view, open, role, dir)`: on the has-overlaps path only, compute `dirs = pendingOverlapDirs(view)` and `activeDir = dir && dirs.includes(dir) ? dir : ""`. When `dirs` is non-empty, append a second label to the card head after the Role label: `<label><span class='sr-only'>Folder</span><select class='field' id='pendingoverlapdir'><option value=''>All folders</option>…</select></label>`. Each directory gets one option with value `esc(d)`, text `esc(d + "/")`, and ` selected` on `activeDir`. A line is kept when it passes the role test (unchanged) and, with an `activeDir`, its path `startsWith(activeDir + "/")`. A derived directory is never itself an overlap path, so that one test matches `inPath` for every option the picker offers. When the role and folder together keep no line, the body is `<div class='empty'>No overlapping file matches the filters</div>`, and the head with both pickers stays so the user can change them. Kept lines keep their unfiltered `data-overlap` index, as today. The no-base, empty and malformed paths are unchanged and render neither picker. Extend the comment above the function: "its Folder picker keeps only the lines at or under the chosen directory (diff --overlaps --path)".
4. `paintPendingOverlaps` passes `pendingOverlapDir` as the fourth argument. In `buildPendingView`'s `change` listener, also handle `e.target.id === "pendingoverlapdir"`: set `pendingOverlapDir`, clear `pendingOverlapOpen`, and repaint, like the role branch. In `fetchPendingOverlaps`, after the existing role reset, reset `pendingOverlapDir` to `""` when `pendingOverlapDirs(pendingOverlaps)` no longer includes it.
5. Update the file's top doc comment ("with Role and Folder pickers that narrow it client-side"). In docs/how-it-works.md, extend the Pending sentence that describes the Role picker with: "and its Folder picker keeps only the files at or under the chosen directory, the `diff --overlaps --path` twin".

**Acceptance criteria** (test/gui-client-pending.test.ts, via `clientScope(["format", "labels", "pending-table"], …)` like the existing Role picker test):
- `pendingOverlapDirs` on overlaps `src/cli/a.ts`, `src/gui/b.ts`, `README.md`, `test/new/` returns `["src", "src/cli", "src/gui", "test", "test/new"]`. It returns `[]` for `null` and for `{ overlaps: "x" }`.
- `pendingOverlapsHtml(view)` renders `id='pendingoverlapdir'`, `<option value=''>All folders</option>` and `<option value='src/cli'>src/cli/</option>`, with no ` selected`.
- `pendingOverlapsHtml(view, null, "", "src")` keeps the `src/cli/a.ts` and `src/gui/b.ts` lines with their indexes 0 and 1. It drops `README.md` and `test/new/`, and marks `<option value='src' selected>`. With `"test/new"` it keeps only the `test/new/` line, at its original index.
- Role and folder combine. Use a role that holds only `src/gui/b.ts` with folder `src/cli`: the result has no `data-overlap` and contains `No overlapping file matches the filters` and both pickers. An unknown folder (`"lib"`) shows every line.
- A view whose only overlap is `README.md` renders the Role picker but no `pendingoverlapdir`. The no-base, `overlaps: []`, `null` and `{ overlaps: "x" }` documents render no `pendingoverlapdir`.
- The existing Pending tests still pass unchanged, and `npm run test:gate` passes.
