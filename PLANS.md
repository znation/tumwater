**Goal.** Each `tumwater wake` mode should read as *run the mode, then report its result*, with the mode's gate-and-work carried by one named helper and the `--json`-or-prose report tail read from a single name. The change is behavior-preserving: every `wake` invocation prints byte-identical stdout (both `--json` and prose), exits with the same code, and writes the same marker files, in every case. The point is that a reader asking "how does the wake `--list`/`--cancel`/`--in` form work, and how does it report?" reads one name per mode, and the duplicated report tail collapses onto the shared helper `sayJsonOrRender` (src/cli/cli-output.ts) that the marker commands already use.

**Approach.** All edits in src/cli/cli-operator-commands.ts; move code, keep every comment with the code it annotates, add no import and remove none except adding `sayJsonOrRender` to the existing cli-output.ts import if the collapsed tail uses it.
- Add module-private `wakeList(root: string, args: string[]): void` holding today's `--list` branch verbatim: the `--in`/`--cancel` rival refusal (`wake --list cannot be combined with --in or --cancel`), the `Date.now()` read, the `namedRoleList(root, args) ?? undefined` scope, the `listWakes` read, and the `say(args.includes("--json") ? JSON.stringify(wakes) : renderWakeList(wakes, now, roles))` report.
- Add module-private `wakeCancel(root: string, args: string[], inRaw: string | null): void` holding today's `--cancel` branch verbatim: the `inRaw !== null` rival refusal, the `optionalFlagValue(args, "--cancel")` positional read, the positional `cancelWakeAtOutcome` path and the bare `cancelWakesOutcome` path, and each path's `--json`-or-prose report.
- Add module-private `wakeRequest(root: string, args: string[], inRaw: string | null): void` holding today's request path verbatim: the `parseDurationFlag` of `inRaw`, the `failOverDurationCap("wake --in", inMs, PAUSE_FOR_MAX_MS)` cap, the `requestWakeOutcome(root, targetRoles(root, args), inMs)` call, and its `--json`-or-prose report.
- Reduce `cmdWake` to: read `inRaw = flagValue(args, "--in")` once, then delegate — `if (args.includes("--list")) return wakeList(root, args);` `if (args.includes("--cancel")) return wakeCancel(root, args, inRaw);` `return wakeRequest(root, args, inRaw);`. The mode-selection order (`--list` before `--cancel` before request) and the shared `inRaw` read are unchanged.
- Collapse the three repeated `if (args.includes("--json")) sayJson(o.payload); else say(o.message);` tails: where a mode's report is exactly that pair for a single outcome, replace it with `sayJsonOrRender(args, o.payload, (p) => o.message)` (the `--json` branch runs first and resolves the payload once; the prose branch prints `o.message`). Where the `--list` form's report is the `JSON.stringify(wakes)` vs `renderWakeList` pair, leave it as-is (its two branches render from the same already-computed `wakes` and the shared helper's render callback does not change what is printed) — the goal is one name per mode, not forcing every tail onto one helper.
