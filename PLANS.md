### Reclaim: `tumwater reclaim --dry-run --json` prints the candidate list as data (planned 2026-10-20 by the plan role; independent of every eligible plan; touches src/operator/operator-commands.ts + src/cli/cli-marker-commands.ts + src/cli/help.ts + docs/cli.md + test/cli-operators.test.ts)

**Goal.** A script that wants to know how much a reclaim would free, or which workspaces sit idle past `worktreeIdleReclaimHours`, has to scrape lines like `feature: idle 25.0h, 2 ignored paths, not idle-reclaimable`. `inspectReclaimCandidates` (src/team/reclaim.ts) already returns structured rows (`name`, `dir`, `idleHours`, `paths`, `resumePending`, `reclaimable`), but `runMarkerCommand` (src/cli/cli-marker-commands.ts) gives `reclaim` only `[DRY_RUN_FLAG]` in `perCommandFlags`, so the unknown-argument gate rejects `--json`. `wake --list --json` is the model: it is a read-only listing with a `--json` twin, and `wake --json` without `--list` fails with `wake --json requires --list`. The real pass (`runManualReclaim`, src/operator/operator-intent.ts) returns one confirmation string and, with a live team, only writes a marker. It has no data to print, so this plan does not touch it: `--json` is a dry-run-only flag.

**Approach.**
1. src/cli/cli-marker-commands.ts: in `runMarkerCommand`'s `perCommandFlags`, change `reclaim: [DRY_RUN_FLAG]` to `reclaim: [DRY_RUN_FLAG, JSON_FLAG]`. `JSON_FLAG` is already imported for `wake`. In the comment above, change "`reclaim` alone accepts `--dry-run`" to "`reclaim` alone accepts `--dry-run` (and `--json` with it)".
2. src/operator/operator-commands.ts `cmdReclaim`: read `const json = args.includes("--json")`. Before the dry-run branch, add `if (json && !dryRun) fail("reclaim --json requires --dry-run");` so the check runs before any pass is requested or run. The wording mirrors `cmdWake`'s `wake --json requires --list`. Inside the dry-run branch, right after `inspectReclaimCandidates` returns, add: when `json`, call `sayJson({ dryRun: true, idleReclaimHours: idleHours, candidates })` and return. This comes before the empty-list `say`, so an empty list prints `"candidates": []` and exits 0. `candidates` is the `ReclaimInspection[]` exactly as returned. `sayJson` is already imported from `../cli/cli-output.js`. The text output stays as it is. Update the doc comment to `tumwater reclaim [--dry-run [--json]]` and add one sentence: `--json` prints the dry run's rows as data.
3. src/cli/help.ts: change the synopsis `tumwater reclaim [--dry-run]` to `tumwater reclaim [--dry-run [--json]]`. In the description's last line, after "and cleans nothing", add `(--json for scripts)`, re-wrapping the column as the `wake` stanza does. Shell completion reads flags from the help stanzas (`helpStanzas` in src/cli/completion.ts), so it needs no separate edit. Confirm that with the gate.
4. docs/cli.md, "Control the roles" row: change `` `tumwater reclaim [--dry-run]` `` to `` `tumwater reclaim [--dry-run [--json]]` ``. After "`--dry-run` lists the candidates and cleans nothing", add `` (`--json` prints them as `{ dryRun, idleReclaimHours, candidates }`, each candidate carrying `name`, `dir`, `idleHours`, `paths`, `resumePending` and `reclaimable`; `--json` without `--dry-run` is refused) ``.

**Files.** src/operator/operator-commands.ts, src/cli/cli-marker-commands.ts, src/cli/help.ts, docs/cli.md, test/cli-operators.test.ts. src/team/reclaim.ts is unchanged, and no docs/invariants.md section binds the reclaim CLI (`grep -n 'cmdReclaim' docs/invariants.md` prints nothing), so this plan claims no invariant ID.

**Acceptance criteria.** All the tests are new, in test/cli-operators.test.ts. Import `worktreeAt` from ./fixtures/repo-fixtures.js beside the existing imports, `worktreeUsePath` from ../src/paths.js, and `writeJsonAtomic` from ../src/files/json-files.js (as test/reclaim.test.ts does).
- "reclaim --dry-run --json prints the candidates as data and cleans nothing": `makeRepo()`, then `await initProject(repo, …)`, then `const wt = worktreeAt(repo, "feature")`. Write `.gitignore` = `build/\n` and `build/out.bin` into `wt`. Then `writeJsonAtomic(worktreeUsePath(repo), { feature: { lastUsedAt: Date.now() - 25 * 3_600_000 } })`. `cli(repo, "reclaim", "--dry-run", "--json")` exits 0. Its whole stdout passes `JSON.parse` with `dryRun: true`, `idleReclaimHours: 24` and one candidate whose `name` is `"feature"`, `paths` is at least 1, `reclaimable` is `true`, and `idleHours` is between 24 and 26. Afterwards `build/out.bin` still exists.
- "reclaim --dry-run --json with no workspaces prints an empty list": a fresh `initProject` repo exits 0, and its stdout parses with `candidates` deep-equal to `[]`. Stdout does not contain `nothing to reclaim`.
- "reclaim --json without --dry-run is refused before any pass": exit 1, stderr matches `/reclaim --json requires --dry-run/`, stdout is empty, and `fs.existsSync(reclaimRequestPath(repo))` is false afterwards (import `reclaimRequestPath` from ../src/paths.js).
