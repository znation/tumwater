### Image-probe cache: a foreign entry in `image-probes.json` is dropped on read instead of throwing out of `tumwater status`, the dashboards' snapshot and the doctor, and docs/invariants.md gains a section for it (planned 2026-10-20 by the plan role; independent of every eligible plan; touches src/doctor/image-probe.ts + test/image-probe.test.ts + test/status-data-models.test.ts + docs/invariants.md)

**Goal.** `readImageProbeCache` (src/doctor/image-probe.ts) returns `readJsonFile<ImageProbeCache>(imageProbesPath(root)) ?? {}`. `readJsonFile` rejects a torn file or a non-object top level, but it does not check the entries, so a `null` (or any non-object) entry reaches callers typed as `ImageProbeCacheEntry`. `imageProbeEntryFresh` tests `entry !== undefined` and then reads `entry.verdict`, and `collectImageProbeFailures` (src/status/status-roles.ts) reads `entry.verdict` on every entry. On 2026-10-20 the plan role confirmed this with a scratch test (since deleted): with `.tumwater/state/image-probes.json` set to `{"pi/a/b": null, "pi/c/d": 7}`, `collectImageProbeFailures(repo)` and `imageProbeEntryFresh(readImageProbeCache(repo)["pi/a/b"])` both throw `TypeError: Cannot read properties of null (reading 'verdict')`. `snapshot` (src/status/status-data.ts) calls `collectImageProbeFailures` on every call, so one hand-edited or foreign entry breaks `tumwater status`, the TUI and the GUI status payload. `tumwater doctor` (the probe loop in src/doctor/doctor-model-checks.ts that calls `imageProbeEntryFresh(probes[key], now)`) throws when the bad entry's key matches a claimed seam. The function's doc comment already promises "a crashed writer never takes down a reader". This plan makes the check per entry too.

**Approach.**
1. src/doctor/image-probe.ts: add an unexported `isImageProbeCacheEntry(value: unknown): value is ImageProbeCacheEntry`: `isJsonObject(value)` (import from ../files/json-object.js), `verdict` is `"pass"` or `"fail"`, `detail` is a string, `at` is a number with `Number.isFinite(at)`, and `claim` is a boolean. `readImageProbeCache` reads `readJsonFile<Record<string, unknown>>(imageProbesPath(root))`, then returns a new object that keeps only the entries passing the check (an empty object for a missing or torn file, as today). Extend its doc comment: an entry of a foreign shape is dropped, so it reads as unprobed, and the doctor's next cache write (`writeImageProbeCache` after a probe) leaves it out. Leave `imageProbeEntryFresh`, `collectImageProbeFailures` and the doctor unchanged: every reader goes through `readImageProbeCache` (check with `grep -rn 'imageProbesPath' src`, which should show only image-probe.ts and paths.ts).
2. test/image-probe.test.ts: append "the probe cache drops a foreign entry and keeps the valid ones". Use `readyRepo()`. Write the file raw with `fs.writeFileSync(imageProbesPath(root), JSON.stringify(...))` (create its directory first; import `fs` and `imageProbesPath` from ../src/paths.js). Include one valid entry plus `null`, `7`, `"fail"`, `{ verdict: "maybe", detail: "x", at: <now>, claim: true }`, `{ verdict: "fail", detail: "x", at: "soon", claim: true }` and `{ verdict: "pass", detail: "x", at: <now> }` (no `claim`). `readImageProbeCache(root)` deep-equals an object holding only the valid entry.
3. test/status-data-models.test.ts: append "a foreign entry in the probe cache leaves collectImageProbeFailures and snapshot standing". Write the file raw (as in step 2) with `"pi/a/b": null` and a fresh `fail` entry under `"pi/huggingface/blind-x"` (`claim: true`, `at: now - 1000`). `collectImageProbeFailures(repo, now)` deep-equals `["huggingface/blind-x"]`, the same label shape as "collectImageProbeFailures keeps a fully-qualified pi model id whole". Then, on a `makeRepo()` + `initProject(repo, "test project")` repo with the same file, `snapshot(repo).imageProbeFailures` deep-equals `["huggingface/blind-x"]`.
   Mutation, applied by hand and reverted: `readImageProbeCache` back to `readJsonFile<ImageProbeCache>(…) ?? {}`. Both new tests should then fail (the status test with the TypeError). Claim in VERIFIED only what you saw.
4. docs/invariants.md: append "## Image-probe cache: a foreign entry reads as unprobed" after the last section. For the INV prefix, run `grep -n '^### INV-' docs/invariants.md | tail` and read the "was free" notes in PLANS.md's Planned entries. On 2026-10-20, BQ had merged, BR (Poll-loop runner state), BS (Pending reverts) and BT (Post-merge reviews) were planned, and BU was free. Use the Guarantee / Binds / Pinned by layout, with one guarantee: `readImageProbeCache` returns only well-formed entries, so a missing, torn or foreign cache file or entry never throws out of `snapshot`, `collectImageProbeFailures` or the doctor's probe check, and a dropped entry reads as unprobed. Binds `readImageProbeCache` and `isImageProbeCacheEntry`. Pinned by the two new tests plus "the probe cache round-trips and a verdict expires after the 7-day TTL" (a valid entry still survives). Cite each test by its full name.

**Files touched.** src/doctor/image-probe.ts (`readImageProbeCache`, one new private guard, an import); test/image-probe.test.ts and test/status-data-models.test.ts (one appended test each, plus imports); docs/invariants.md.
