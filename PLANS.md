### The pre-queue self-check flags a word doubled by a word-swap rename ("role role", "merge merge") in added comment and doc prose (planned 2026-10-20 by the plan role; independent of every eligible plan; touches src/run/stage-path-checks.ts + src/run/stage-check.ts + test/stage-check.test.ts + test/gui-operator.test.ts + src/git/worktree-use.ts)

**Goal.** Every plain-terms rename pass has left words doubled in comments, and reviewers rejected the change for each one. Between 2026-10-17 and 10-20, `review_rejected` reasons quote "The merge merge's conflict resolver", "eight newly introduced "role role(s)" artifacts", "a role role's bare nothing-to-do" (split across a line break), "an idle role role shows why…" and "(config, roles, roles, running, …)". `garbledWordingFindings` (src/run/stage-path-checks.ts) already catches this for "run" (`GARBLED_WORDING`'s `\bruns?\s+run(?:s|ning)?\b`), but not for any other word, so the next rename (`loop` → `role`, `landing` → `merge`) reaches review with it. This plan adds a word-agnostic doubled-word pattern that runs only on comment and doc prose, so the authoring session gets the finding in its fix-up turn instead of losing a review round. `grep -n -iE 'doubled word|repeated word|role role' PLANS-DONE.md BUGS-FIXED.md` printed nothing when planned. The closest finished plans are the two garbled-wording entries ("…flags the garbled wording a word-swap rename leaves…" and "…catches "run" stacked on "run"…"), and both cover "run" only.

**Approach.** All in src/run/stage-path-checks.ts, beside `GARBLED_WORDING`:
1. Add `const DOUBLED_WORD = /(?<![-./\w])(?!(?:that|had)\b)([A-Za-z]{2,})\s+\1\b(?![-:])/;` with a doc comment. It is case-sensitive on purpose, so `[object Object]` and "plans PLANS" do not match. The lookbehind skips a word after `-`, `.` or `/` ("team-wide wide-shallow", "built-in in", "Readable.read read", "chars/line line"). The trailing lookahead skips "NaN NaN:NaN" and "not not-ready". "that that" and "had had" are grammatical and are let through.
2. Add `function proseOf(file: string, line: string): string | null`. It returns the whole line for a `.md` file and for a line whose trimmed start is `//`, `/*` or `*`, and the text from the first ` // ` onward for a trailing comment. Otherwise it returns null. Code is never checked, because class strings like `"btn btn-sm"` would match.
3. `spanningGarbled(joined, joinAt)` gets a third parameter `patterns: readonly RegExp[]`. The existing call passes `GARBLED_WORDING`.
4. In `garbledWordingFindings`, when no `GARBLED_WORDING` pattern hit the line and `proseOf(file, cur)` is not null, test `DOUBLED_WORD` against that prose. A match is pushed as `${file}:${lineNo} "${m[0]}"`, like the existing hits. In the split-line branch, when the `GARBLED_WORDING` spanning check finds nothing and both `proseOf(file, prevAdded)` and `proseOf(file, cur)` are non-null, call `spanningGarbled(joined, head.length, [DOUBLED_WORD])` and report a hit as `${file}:${lineNo - 1}-${lineNo}`. Record prose stays skipped through the existing `isRecordProse` guard. A line still yields at most one hit.
5. Change the finding's lead to `'added lines carry garbled rename wording (reword them; a rote word swap such as "tick" → "run" reads wrong here or leaves a word doubled): '`. Keep the `// vocabulary-ok` marker on that line and the "garbled rename wording" substring, which existing tests filter on.
6. Doc comments: in the module comment of src/run/stage-path-checks.ts, change "garbled run wording" to "garbled run wording or a doubled word in comment and doc prose". In src/run/stage-check.ts, extend the "seventh check" paragraph with one sentence: it also reports any word doubled back to back in comment or doc prose (case-sensitive, not after `-`, `.` or `/`, "that that" and "had had" excepted).
7. Fix the two hits this pattern finds on the tree today. test/gui-operator.test.ts has the comment "every idle role role as `waiting: budget spent`", which becomes "every idle role as …". src/git/worktree-use.ts has "process that runs runs and merges" in its module comment, which becomes "process that launches runs and merges". When planned, a node script that applied `DOUBLED_WORD` through `proseOf` to every line of the .ts/.tsx/.md files under src, test and docs, plus README.md and DEVELOPMENT.md, found exactly these two hits in 64,117 prose lines.

**Files.** src/run/stage-path-checks.ts, src/run/stage-check.ts (doc comment only), test/stage-check.test.ts, test/gui-operator.test.ts (comment only), src/git/worktree-use.ts (comment only).
