### Run end: a failed role-state save in `finalizeRun` warns and still logs `run_end`, instead of rejecting the run task and skipping the breaker fold (planned 2026-10-20 by the plan role; independent of every eligible plan; touches src/run/run-finalize.ts + src/runner/runner-state.ts + test/run-finalize.test.ts + docs/invariants.md)

**Goal.** `finalizeRun` (src/run/run-finalize.ts) runs after the pi run, and for a `queued` result after the change is already in the merge queue. It folds the outcome with `applyRunOutcome`, releases a finished claim, calls `restoreMidRunWake`, then calls `saveRunnerState(root, s)` with no guard. After that come the streak warnings, the `observeClaudeAccount` fold and the `run_end` event. `runPhase` (src/runner/runner-run.ts) says it "Never throws", but a failed save rejects it: the `run_end` event is never logged (so the run's spend, duration and result never reach the feed the report and the failure digest read), and `ctx.setRunPair(undefined)` never runs. The rejection also skips the rest of the launch task in `launchDueRuns` (src/orchestrator/orchestrator-launch.ts): the fallback breaker's `recordFallbackRunAt` evidence fold and, for a probe, `abandonFallbackProbeAt`. That task's `.catch` only sets `running = false` and warns "run task rejected: …", so a probe run whose save fails leaves its claim on the pair. On 2026-10-20 the plan role confirmed the rejection with a scratch test (since deleted) in a copy of test/run-finalize.test.ts. It installed `failRenameSyncOn(statePath(root, "feature-2"), "EACCES fake")` and called the file's `run(root, "feature-2", freshRunnerState("feature-2"), { result: "queued", summary: "x" })` helper. The call rejected with `Error: EACCES fake`, `s.running` was false (the fold had already happened in memory), and `eventsOfType(root, "run_end")` was empty. The in-memory state already holds everything the save would write, and the runner's next save (a skip reason, a merge write-back, the next run's end) writes it to disk. So a best-effort save loses nothing the team needs. This narrows the Poll-loop runner state plan's (PLANS-DONE.md) "run-end and CLI callers keep their errors": `saveRunnerState` itself stays strict, and CLI callers keep their errors.

**Approach.**
1. src/run/run-finalize.ts, `finalizeRun`: replace `saveRunnerState(root, s)` with `saveRunnerStateBestEffort(root, s)`. Swap the import from ../runner/runner-state.js (keep `hasOutstandingWork` and the `RunnerState` type, and drop `saveRunnerState` once `grep -n 'saveRunnerState(' src/run/run-finalize.ts` finds no other call). Add one sentence to the comment above the save, or to `finalizeRun`'s doc comment: a failed save warns and the run still ends normally, because the in-memory state already holds the fold and the runner's next save writes it.
2. src/runner/runner-state.ts, `saveRunnerStateBestEffort`'s doc comment: it now names two callers, not just "the orchestrator's poll loop, which has no catch". Reword it to cover the poll loop and the run's end, where a throw would skip `run_end` and the launch task's breaker fold. Do not change the code.
3. test/run-finalize.test.ts: after "an unwritable events feed cannot reject finalizeRun — the outcome still folds and saves", add "a failed role-state save cannot reject finalizeRun — run_end still logs and the run warns". Import `failRenameSyncOn` from ./helpers/fs-faults.js, add `statePath` to the existing ../src/paths.js import, and add `warningMessages` to the existing ./fixtures/log-fixtures.js import. Use `initializedRepo()` and `freshRunnerState("feature-2")`. Install the fault before calling `run(root, "feature-2", s, { result: "queued", summary: "queued it" })`, and undo it in a `finally`. Assert that the call resolves with `result` `"queued"`, that `s.running` is false, that `eventsOfType(root, "run_end")` has one event with `result` `"queued"`, and that `warningMessages(root)` holds exactly one entry matching `/could not save the role's state: EACCES fake/`. Check `warningMessages`'s and `eventsOfType`'s signatures in test/fixtures/log-fixtures.ts before using them.
4. docs/invariants.md: append "## Run end: a failed state save still ends the run" after the last section, using the Guarantee / Binds / Pinned by layout. For the prefix, run `grep -n '^### INV-' docs/invariants.md | tail` and read the "was free" notes in PLANS.md's Planned entries. On 2026-10-20, BU, BV and BW had merged, BX (Merge write-back) was planned, and BY was free. Write one guarantee: `finalizeRun` resolves with the run's outcome and logs `run_end` even when the role's state save or the events feed fails; a failed save warns under the role's id. Binds `finalizeRun` and `saveRunnerStateBestEffort`. Pinned by the new test plus "an unwritable events feed cannot reject finalizeRun — the outcome still folds and saves" and "finalizeRun folds the outcome onto the state, persists it, and logs run_end". Cite each test by its full name.

**Acceptance criteria.**
- With step 1 reverted (back to `saveRunnerState`), the new test fails because `finalizeRun` rejects with `EACCES fake`.
- `npm run test:gate` passes.
- `git diff --stat` shows src/run/run-finalize.ts and src/runner/runner-state.ts as the only changed src/ files, and runner-state.ts's diff touches only a comment.

### OpenCode catalog seed: a malformed models.dev body or a failed cache write no longer rejects `tumwater start` (planned 2026-10-20 by the plan role; independent of every eligible plan; touches src/agent/opencode/opencode-catalog.ts + test/opencode-catalog.test.ts + docs/invariants.md)

**Goal.** `runStartupCheck` (src/gates/startup-gate.ts) awaits `refreshOpencodeCatalog` with no catch whenever a model job routes to opencode. Its comment says "a failed fetch keeps the last good cache (or an empty one) and never blocks startup". That holds only for a fetch that throws. Two other failures reject the refresh, and with it `runStartupCheck`, so `tumwater start` (src/cli/cli-start.ts awaits `runStartupCheck` with no catch) dies on a stack trace:
- `parseOpencodeCatalog` casts the fetched body instead of checking it. `Object.entries(providerInfo.models)` throws when a kept provider's `models` is `null`. `m.modalities.input.includes` throws when `input` is not an array or string, and `m.reasoning_options?.filter` throws when `reasoning_options` is not an array. A wrong-typed field passes through silently instead. `cost: { input: "0", output: 0 }` yields `inputPerM: "0"`, which the cache then holds, typed as a number, until the next read drops it.
- `writeOpencodeCache(root, cache)` in `refreshOpencodeCatalog` has no guard, so an unwritable `.tumwater/state/opencode-models.json` rejects the refresh. The cache stays stale, so every later start fails the same way.
On 2026-10-20 the plan role confirmed all of these with a scratch test (since deleted). Each of `{ opencode: { models: null } }`, `{ opencode: { models: { m: { modalities: { input: 5 } } } } }` and `{ opencode: { models: { m: { reasoning_options: { type: "effort" } } } } }` made `parseOpencodeCatalog(body, [])` throw a TypeError. The `cost` body above returned `{"opencode/m":{"free":false,"inputPerM":"0","outputPerM":0}}`. `refreshOpencodeCatalog` rejected when a directory sat at `opencodeModelsPath(root)`. "OpenCode catalog cache" in PLANS-DONE.md guarded the read side and deliberately left the parse out of scope; this plan covers the parse.

**Approach.**
1. src/agent/opencode/opencode-catalog.ts, `parseOpencodeCatalog`: make it total over any `body`. Skip a provider unless `isJsonObject(providerInfo?.models)`, and skip a model entry unless `isJsonObject(raw)`. Read `cost` only when `isJsonObject(m.cost)` and `limit.context` only when `isJsonObject(m.limit)`, as today otherwise. Set `images` only when `Array.isArray(m.modalities?.input)`, with `modalities` checked by `isJsonObject` first. Compute `efforts` only when `Array.isArray(m.reasoning_options)`: keep the elements that pass `isJsonObject` and have `type === "effort"`, and flatMap each one's `values` when `Array.isArray`, else `[]`. Finally store the model only when `isOpencodeCatalogModel(model)` holds (the existing guard the cache read uses). That drops a model with a non-finite or non-number price, context or effort, so it reads as missing from the catalog, which means "not free", the safe direction for the budget gate. Add one sentence to the doc comment: the body is untrusted network data, and a malformed provider or model is skipped, never thrown on.
2. Same file, `refreshOpencodeCatalog`: wrap `writeOpencodeCache(root, cache)` in `try`/`catch`. The `catch` calls `opts.warn?.(\`could not save the open code model catalog: ${errorMessage(err)}\`)` and the function still returns `cache`. Import `errorMessage` from wherever the other src/ files take it (`grep -rn 'export function errorMessage' src`). Extend the function's doc comment: a failed cache write warns and returns the fetched catalog, so the next start fetches again. Leave startup-gate.ts alone. It passes no `warn` today, and wiring that up is a separate change.
3. test/opencode-catalog.test.ts: append two tests.
   - "parseOpencodeCatalog skips a malformed provider or model instead of throwing": the body is `{ opencode: { models: { a: { modalities: { input: 5 } }, b: { reasoning_options: { type: "effort" } }, c: { cost: { input: "0", output: 0 } }, d: null, ok: { cost: { input: 0, output: 0 } } } }, "opencode-go": { models: null } }` with providers `["opencode-go"]`. `assert.deepEqual` the result to `{ "opencode/a": { free: false }, "opencode/b": { free: false }, "opencode/ok": { free: true, inputPerM: 0, outputPerM: 0 } }`.
   - "a failed catalog write warns and still returns the fetched catalog": on `tmpdir()`, `fs.mkdirSync(opencodeModelsPath(root), { recursive: true })` so a directory blocks the atomic rename. Call `refreshOpencodeCatalog` with `providers: []`, `fetch: fetchOf(catalogCapture())`, `cliVersion: "2.0.32"`, `now: () => 1_000` and a `warn` that collects messages. It resolves with `fetchedAt` 1_000 and `models["opencode/deepseek-v4.1-flash-free"]?.free === true` (the model "a failed fetch keeps the old cache and logs one warning" already reads). Exactly one warning starts with `could not save the open code model catalog`.
4. docs/invariants.md: append "## OpenCode catalog seed: a refresh never rejects the startup check" after the last section, using the Guarantee / Binds / Pinned by layout. For the prefix, run `grep -n '^### INV-' docs/invariants.md | tail` and read the "was free" notes in PLANS.md's Planned entries. On 2026-10-20, BU, BV and BW had merged, BX (Merge write-back) and BY (Run end) were planned, and BZ was free. Write one guarantee: `refreshOpencodeCatalog` resolves for any fetched body and any cache-write failure. It drops a malformed upstream model rather than storing it or throwing, and a failed write warns through `opts.warn`. Binds `parseOpencodeCatalog`, `refreshOpencodeCatalog` and `isOpencodeCatalogModel`. Pinned by the two new tests plus "a failed fetch keeps the old cache and logs one warning". Cite each test by its full name.

**Acceptance criteria.**
- With step 1 reverted, the first new test fails with a TypeError. With step 2 reverted, the second new test fails because the refresh rejects.
- The existing parse tests (the 2.0.32 capture) still pass unchanged.
- `npm run test:gate` passes.

- Each test name cited in the new section exists verbatim (`grep -rF` each one in test/).
