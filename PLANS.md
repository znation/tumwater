**Goal.** Pin the one unpinned collections *median* rule in `test/collections.test.ts`. `lowerMedian` is the single home of the lower-median rule that the report per-day medians, the backlog-lag median, and the doctor duration/wait phrase rows all read (directly or through `medianAndMax`), and the rule its doc comment pins against the `failure-data.ts` twin is a genuinely multi-branch one: odd count → the single middle; even count → the *lower* of the two middles. Pin both branches and the one mean-contrast discriminator with plain `assert` in the existing test file.

**Approach.** One file, no new dependency, no src change, no invariant edit. In `test/collections.test.ts` (which already imports from `../src/collections.js`), add `lowerMedian` to the import list and add one `test(…)` block named for the rule (e.g. `"lowerMedian takes the lower of the two middles for an even count"`), with plain `assert.equal` / `assert.deepEqual` cases whose expected values are derived from the definition (`sorted[Math.floor((sorted.length - 1) / 2)]` over an ascending sort of a fresh copy), not from calling the function:
- odd count → the single middle: `lowerMedian([1,2,3,4,5])` is `3`.
- even count → the lower of the two middles (the mean-contrast discriminator — the regression this pin guards against): `lowerMedian([1,2,3,4])` is `2`. `failure-data.ts`'s `median` of the same input would be the mean, `2.5`; a regression that "unified" `lowerMedian` to the mean-of-two would fail this `assert.equal(2)`.
- smallest counts: `lowerMedian([7])` is `7` (count 1 → index 0); `lowerMedian([2,5])` is `2` (count 2 → index 0, the lower of the two).
- the fresh-copy guarantee the doc comment binds (the input is never mutated): after `const input = [4,1,3,2]; lowerMedian(input)`, `input` is still `[4,1,3,2]` and the call returned `2`.

Each expectation is computed from the definition (index `Math.floor((n-1)/2)` into the ascending-sorted values), not from a call to `lowerMedian`.

**Files touched.** `test/collections.test.ts` only — extend the existing `import { … } from "../src/collections.js"` with `lowerMedian` and add the one test block. No `src/` file changes; no `docs/invariants.md` edit (no collections section exists).

**Acceptance criteria.**
- Given the odd-count list `[1,2,3,4,5]`, `lowerMedian` returns `3` (the single middle).
- Given the even-count list `[1,2,3,4]`, `lowerMedian` returns `2` — the lower of the two middles, the exact value `failure-data.ts`'s mean-of-two `median` would not give (`2.5`), so a regression that routed it to the mean would fail this case.
- Given the single value `[7]` it returns `7`; given the two values `[2,5]` it returns `2`.
- Given an unsorted input, the call sorts a copy and leaves the caller's array byte-identical (e.g. `[4,1,3,2]` is unchanged after the call and yields `2`).
- `test/collections.test.ts` runs green with the added cases, and the file's existing `rankCountEntries`/`sortByValueDesc`/`topAndHidden` cases pass unchanged (the pin is an addition; it changes no source behavior).
