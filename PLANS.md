## Planned

### `commitTier`'s three-way role classification is pinned in test/roles.test.ts, so a regression in the one home of the work/maintenance split the report's per-day work vs maintenance commit counts, the maintenance-quota gate, the doctor holds row, and the status maintenance poll all read through — feature/bugfix/director are `"work"`, readme plus the eight code-maintenance roles are `"maintenance"`, and every other role (plan, steward, the four observers, unknown/custom) is `undefined` — is caught by the suite (planned 2026-11-16 by the plan role; continues the pin-a-rule family — `lowerMedian` (test/collections.test.ts) and the recent `compareCodeUnits`, `validEntries`, `filterKeepPositions`, `setOwn`, `checkMinRunInterval`, `isPlainDecimal`/`isExponentSpelling` and `fallback`-chain entries each take one correct-but-unpinned single-home rule and pin it in its natural test file with plain `assert`. `commitTier(role: string): "work" | "maintenance" | undefined` in src/roles/roles.ts is a three-way decision table over `baseRoleOf(role)`: `feature`/`bugfix`/`director` → `"work"`; `readme` or any of the eight `CODE_MAINTENANCE_ROLES` (`organize`, `coverage`, `clean`, `dedupe`, `perf`, `security`, `robustness`, `improve`) → `"maintenance"`; otherwise `undefined`. It is exported and is the one pure, genuinely multi-branch classification whose own rule no test file references: `grep -rlw commitTier test/` is empty — while `src/` imports it from seven sites (`src/gates/maintenance-quota-gates.ts`×2, `src/scheduling/scope.ts`, `src/scheduling/skip.ts`, `src/doctor/doctor-holds.ts`, `src/status/status-polls.ts`, `src/report/report-data.ts`, plus `src/report/report-usage-fold.ts`) and `src/roles/roles.ts` is already tested (test/roles.test.ts imports and pins the sibling classification exports `DEFERRABLE_ROLES`, `OBSERVER_ROLES`, `allRoleIds`, `roleById`) — so the *shape* of roles.ts is pinned but this specific rule is not. Its sibling `roleTier` is a coarser two-value rule (work vs everything-else) and is pinned transitively; `commitTier` is the finer three-way rule the work-vs-maintenance *report and quota* actually split on, and it is the unpinned one. The contrast with `roleTier` is deliberate and load-bearing: `commitTier` returns `undefined` for `plan` and `steward` (which `roleTier` folds into the one "everything else" bucket) and for the four observer roles (`qa`, `ci`, `selfcheck`, `feedback`) — the report counts them in the total commits but in neither the work or the maintenance figure, so the two tier counts need not sum to the day's total. A reader who misreads a branch — treating `plan` as `"maintenance"`, or dropping the `bugfix`/`director` work members, or returning `"work"` for `steward` — passes every existing test (none imports `commitTier`) and silently miscounts the per-day work/maintenance split and the maintenance-quota allowance: a `plan` merge that becomes `"maintenance"` would wrongly spend the maintenance allowance. Because the `CODE_MAINTENANCE_ROLES` array is module-private (only its eight members are reachable through `commitTier`), the pin must enumerate all nine maintenance members explicitly — `readme` plus the eight — to cover the `"maintenance"` branch without importing the private constant. `baseRoleOf` (`src/roles/runner-ids.ts`) resolves an instance id to its base role, so the instance cases (`"feature-2"`, `"clean-3"`) exercise that fold, not just the bare-id table. `docs/invariants.md` has no roles/commitTier section, so no invariant edit is needed; touches test/roles.test.ts only. Independent of the `lowerMedian` entry above (different rule, different test file — both are additions to their own files and neither imports the other)

**Goal.** Pin the one unpinned three-way role-classification rule in `test/roles.test.ts`. `commitTier` is the single home of the work-vs-maintenance split the report's per-day `workCommits`/`maintenanceCommits`, the maintenance-quota gate's window count, the doctor holds row, and the status maintenance poll all read through, and its three arms (`"work"` = the shipping tier, `"maintenance"` = code upkeep plus readme, `undefined` = everything else) are a genuinely multi-branch rule its own doc comment names but no test references. Pin all three arms, the instance-id fold through `baseRoleOf`, and the `roleTier`-contrast discriminator (the `undefined`-but-tier-1 members) with plain `assert` in the existing test file.

**Approach.** One file, no new dependency, no src change, no invariant edit. In `test/roles.test.ts` (which already imports `DEFERRABLE_ROLES`, `DIRECTOR_ROLE`, `OBSERVER_ROLES`, `ROLES`, `allRoleIds`, `roleById`, `unknownRoleMessage` from `../src/roles/roles.js` and already pins the catalog's shape), add `commitTier` to the import list and add one `test(…)` block named for the rule (e.g. `"commitTier classifies the work, maintenance, and un-tiered roles"`), with plain `assert.equal` cases whose expected values are read from the rule in src/roles/roles.ts, not from calling the function:
- the `"work"` arm — the shipping tier: `"feature"` is `"work"`, `"bugfix"` is `"work"`, `DIRECTOR_ROLE` (`"director"`) is `"work"`.
- the `"maintenance"` arm — enumerate every one of the nine members: `"readme"` and each of `"organize"`, `"coverage"`, `"clean"`, `"dedupe"`, `"perf"`, `"security"`, `"robustness"`, `"improve"` is `"maintenance"`.
- the `undefined` arm — the un-tiered roles the `roleTier` coarsening folds into "everything else" but `commitTier` deliberately keeps out of both tiers: `"plan"` is `undefined`, `"steward"` is `undefined`, and each observer (`"qa"`, `"ci"`, `"selfcheck"`, `"feedback"`) is `undefined`; an unknown or custom id (`"myrole"`) is `undefined`.
- the instance-id fold through `baseRoleOf`: `"feature-2"` is `"work"`, `"clean-3"` is `"maintenance"`, `"plan-2"` is `undefined` — the instance number never changes the tier.

Each expectation is read from the `if / if / return` table in src/roles/roles.ts (the three arms over `baseRoleOf`), not from a call to `commitTier`; the maintenance members are enumerated by name because `CODE_MAINTENANCE_ROLES` is module-private and only reachable through `commitTier`.

**Files touched.** `test/roles.test.ts` only — extend the existing `import { … } from "../src/roles/roles.js"` with `commitTier` and add the one test block. No `src/` file changes; no `docs/invariants.md` edit (no roles/commitTier section exists).

**Acceptance criteria.**
- `commitTier` returns `"work"` for `"feature"`, `"bugfix"`, and `"director"`; `"maintenance"` for each of `"readme"` and the eight `"organize"`/`"coverage"`/`"clean"`/`"dedupe"`/`"perf"`/`"security"`/`"robustness"`/`"improve"`; and `undefined` for `"plan"`, `"steward"`, `"qa"`, `"ci"`, `"selfcheck"`, `"feedback"`, and an unknown id such as `"myrole"`.
- `commitTier` returns `"work"` for `"feature-2"` and `"maintenance"` for `"clean-3"` — the instance suffix resolves to the same tier as the bare base role through `baseRoleOf`.
- The three arms are disjoint and cover every role id (`commitTier` maps all 18 — the 17 catalog roles plus the director): `"work"` = `feature`/`bugfix`/`director`, `"maintenance"` = `readme` + the eight code-maintenance roles, `undefined` = `plan`/`steward`/`qa`/`ci`/`selfcheck`/`feedback`/unknown — so a branch that moved a role to the wrong arm (e.g. `"plan"` → `"maintenance"`, or `"steward"` → `"work"`) fails the matching arm's case.
- `test/roles.test.ts` runs green with the added cases, and the file's existing `DEFERRABLE_ROLES`/`OBSERVER_ROLES`/`allRoleIds`/`roleById`/`unknownRoleMessage` cases pass unchanged (the pin is an addition; it changes no source behavior).
