The entry is gone, the commit is on main permanently beyond the review gate, and nothing escalates it: `tumwater reviews` (its `[N failed review runs]` suffix, src/review/post-review-render.ts) and the dashboard/TUI Pending views list the state but never call it a problem, and no doctor row or team alert reads `readPostReviews` (`grep -rn "readPostReviews" src/doctor src/ui/team-alerts.ts` matches nothing today). At `failures === POST_REVIEW_FAILURE_LIMIT - 1` the next failed run drops the commit, so that at-risk window is the last moment an operator can act: fix the reviewer backend, or accept the commit as unreviewed deliberately. This adds the missing judgment: a `post-merge reviews` doctor row and a standing amber alert off one shared traversal and one shared sentence, so both surfaces select the same entries and say the same thing.

**Approach.**

Add `export const POST_REVIEW_AT_RISK_FAILURES = POST_REVIEW_FAILURE_LIMIT - 1;` (doc-commented: the entry the next failed run drops), `export interface AtRiskPostReview { commit: string; role: string; summary: string; failures: number }`, `export function atRiskPostReviews(root: string): AtRiskPostReview[]` — `readPostReviews(root).filter((e) => (e.failures ?? 0) >= POST_REVIEW_AT_RISK_FAILURES).map((e) => ({ commit: e.commit, role: e.role, summary: e.summary, failures: e.failures ?? 0 }))`, in file (FIFO) order, and `export function atRiskPostReviewsPhrase(rows: readonly AtRiskPostReview[]): string | null` — `null` for an empty list, else the doctor's one sentence: `the post-merge review of ${roleLabel(first.role)} ${shortSha(first.commit)} — "${truncate(first.summary, FIX_CLAIM_HEADING_MAX)}" — has ended without a verdict ${first.failures} times${andMore(rest, (r) => `${roleLabel(r.role)} ${shortSha(r.commit)}`)}; one more failed run drops it and the commit stays on main unreviewed — fix the reviewer backend or accept the commit unreviewed deliberately`. These two functions plus `checkPostReviews` are the ONE traversal and ONE sentence the doctor row and the alert share, so the trigger and the wording cannot drift (`roleLabel`, `truncate`, `andMore` and `FIX_CLAIM_HEADING_MAX` already live in this module).
