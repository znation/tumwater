### TUI transcript search: `/` on a role's live Transcript view keeps only the entries that contain the text, each under its run's separator, the terminal twin of the dashboard drawer's transcript search box (planned 2026-10-20 by the plan role; independent of every eligible plan. "The TUI's change step lists the viewed role's waiting merges" edits the Ctrl+N change step in src/ui/tui/tui-pane-transcript.ts. This plan adds a separate field and method to the same module, so whichever lands second rebases. Touches src/ui/tui/tui-editor-search.ts + src/ui/tui/tui-editor-ctx.ts + src/ui/tui/tui-editor-session.ts + src/ui/tui/tui-editors.ts + src/ui/tui/tui-keys.ts + src/ui/tui/tui-panes.ts + src/ui/tui/tui-pane-transcript.ts + src/ui/tui/tui-pane.ts + src/ui/tui/tui-frame.ts + src/ui/tui/tui.tsx + docs/cli.md + test/tui-keys.test.ts + test/tui-frame.test.ts + test/transcript.test.ts)

**Goal.** `tumwater logs --transcript <id> --grep <text>` and the dashboard drawer's "Search transcript" box (`GET /api/transcript?…&grep=`, PLANS-DONE.md "Transcript search in the dashboard, part 2/2") both narrow a role's transcript to the entries that contain the text. The TUI cannot do this. Its shared `/` search editor (`createSearchEditor`, src/ui/tui/tui-editor-search.ts) opens only on Activity, Backlog and History. On a role's Transcript view `/` types into the prompt (test/tui-keys.test.ts asserts "`/` on a transcript types into the prompt"). `paneBody` (src/ui/tui/tui-pane.ts) paints `readTranscript(root, pane.role, eventBudget)` with no filter. This plan adds a fourth `/` target, the live transcript step of a role view. It reuses `readTranscript`'s existing `grep` option, which applies `createTranscriptFilter` (src/ui/transcript.ts), so the CLI, the dashboard and the TUI share one keep rule. When planned, `grep -rn 'transcriptGrep' src/ui/tui test` printed nothing.

Behavior, decided:
- `/` opens the search on a role view (`ctx.view >= 1 && ctx.view <= ctx.roleIds.length`) only while the live transcript step is shown (`!ctx.noteMode && !ctx.changeMode`) and the prompt line is empty, the same empty-line guard the other targets use. On the notes and change steps, `/` still types into the prompt.
- The pattern belongs to the role it was applied on. Every Ctrl+T cycle clears it (`reset()`), so each role's view opens unfiltered, matching the drawer's per-role reset. Ctrl+N to notes and back keeps it. A roster shift that puts another role at the same index does not apply it: the module stores `{ role, pattern }`, and `state()` reports `transcriptGrep` only while `session.roleIds[session.view - 1] === role`.
- The match is case-insensitive. The pane passes the pattern lowercased, because `createTranscriptFilter` expects an already-lowercased needle, and `handleTranscript` (src/gui/gui-endpoints.ts) does the same.
- Filtered, the pane scans the last 200 entries, which is the drawer's `n=200` (`readTranscript` clamps to its own `MAX_ENTRIES`). It keeps the last `eventBudget` lines of the result. Unfiltered painting stays exactly as it is now.

**Approach.**
1. src/ui/tui/tui-pane-transcript.ts `createTranscriptPane`: add `let transcriptSearch: { role: string; pattern: string } | null = null;`. Clear it in `reset()`. Add a method `applySearch(pattern: string | null): void` that sets `transcriptSearch = pattern === null ? null : { role: session.roleIds[session.view - 1]!, pattern }`, sets `session.paneScroll = 0`, and calls `session.requestRender()`. Do nothing when the view is not a role view. `state()` adds `transcriptGrep: transcriptSearch !== null && session.roleIds[session.view - 1] === transcriptSearch.role ? transcriptSearch.pattern : null`. Widen the `satisfies` clause the way tui-pane-backlog.ts does for its `applySearch`. Update the header comment to mention the `/` search.
2. src/ui/tui/tui-panes.ts: the `state()` assembly adds `transcriptGrep: tra.transcriptGrep` beside `changeCache`. `editorCtx()` adds `transcriptGrep: s.transcriptGrep` and `changeMode: s.changeMode`. The returned object adds `applyTranscriptSearch: transcript.applySearch` beside `applyBacklogSearch`.
3. src/ui/tui/tui-editor-ctx.ts `TuiEditorCtx`: add `transcriptGrep: string | null` (doc: "The viewed role's live-transcript search (the `/` editor's applied pattern).") after `backlogGrep`. Add `changeMode: boolean` (doc: "Whether the viewed role's pane shows its change step (the second Ctrl+N step)") after `noteMode`.
4. src/ui/tui/tui-editor-session.ts and src/ui/tui/tui-editors.ts: add `applyTranscriptSearch(pattern: string | null): void` beside `applyBacklogSearch` in the session interface, the deps interface (doc: "Apply a finished Transcript search on the viewed role's pane (sets its pattern, resets the scroll).") and the deps pass-through. src/ui/tui/tui-keys.ts: the state type gains `transcriptGrep: string | null` beside `backlogGrep`, and `createTuiEditors({...})` gains `applyTranscriptSearch: panes.applyTranscriptSearch`.
