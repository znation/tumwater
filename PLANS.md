### The `fallback` chain's list-element rules and the "a provider/model id named on the `claude` backend" rule are pinned in test/config-selector-checks.test.ts, so a regression in these two unpinned branches of the model-selector fallback chain — the rules that keep a `fallback` list's elements and a paid-model mis-price from passing validation silently — is caught by the suite (planned 2026-11-15 by the plan role; `checkFallbackList(name, list, problems, inheritedBackend)` and `checkRetiredSelector(name, v, backend, problems)` in src/config/config-selector-checks.ts are the model-selector fallback-chain validators `validateConfig` runs on each model-choosing section; the empty-half, id-names-backend, and bare-claude-id selector branches are already pinned end-to-end through `validateConfig` in test/config-validation.test.ts and test/config-validation-model.test.ts, but the list-element rules and the provider/model-id-on-`claude`-backend rule have no exact-string test — `grep -rn --include='*.test.ts' -E 'name at least one model id|non-empty model id or a step object|only valid as a whole-tier|is a provider/model id' test/` prints nothing, and test/config-selector-checks.test.ts does not exist; independent of the other `## Planned` entry, which pins src/text/text.ts through test/text.test.ts — these pin src/config/config-selector-checks.ts through test/config-selector-checks.test.ts, and the two share no src module, test file, or named import — so feature may take either; docs/invariants.md binds the `fallback` guarantees through the validators' tests, not through this module's internal branch shape, so no invariant edit is needed)

**Goal.** Pin the two genuinely-unpinned branches of the model-selector fallback chain. `checkFallbackList` is the one home of the `fallback`-list element rules — a list must be non-empty, and each element must be either a non-blank model-id string, an object step, or (for a *string*) a legitimate model id and not the whole-tier-only `"pause"` — whose message wording no test pins, and which no test drives directly. `checkRetiredSelector` is the one home of the retired-spelling rules a model id may trip; of its three branches the middle one — a provider/model id (a `provider/…` selector) named on the `claude` backend — is unpinned, and that is the rule that would let a config pay claude's per-token rate for a model that should run free. Pin both functions directly, each branch as an observable problem message, in a new test file.

**Approach.** One file, test-only, no src change and no invariant edit: create test/config-selector-checks.test.ts (importing `checkFallbackList` and `checkRetiredSelector` from `../src/config/config-selector-checks.js`) and pin the branches with plain `assert` on the exact problem strings they push (these strings are the contract `validateConfig` surfaces, so byte-exact quoting is the intended pin — the em-dash `—` is a U+2014, and the values appear JSON-quoted because the rule renders them through `show()`). `checkFallbackList` drives its three branches in isolation (each call a fresh `problems` array, `inheritedBackend` left at its default `"pi"`): the empty list, a non-blank / non-string element, a `"pause"` element, and a clean selector list that pins nothing (a negative). `checkRetiredSelector` drives its one unpinned branch (a provider/model id on the `claude` backend) with a clean (no-`/`) selector that pins nothing as its negative; its other two branches (id-names-backend, bare-claude-id) are already pinned end-to-end, so they are not re-asserted here. Each case is one assert; no repo, worktree, fs, git or clock.

**Files touched.** test/config-selector-checks.test.ts (new).

**Acceptance criteria.**
- Given an empty `fallback` list, `checkFallbackList("fallback", [], problems)` pushes exactly one problem, whose text is `fallback list must not be empty — name at least one model id`.
- Given a `fallback` list whose element is a blank string, the problem pushed is `fallback list element 1 must be a non-empty model id or a step object (got "")`; given a list whose element is the number `5`, it is `fallback list element 0 must be a non-empty model id or a step object (got 5)` — the element must be a non-blank string or an object step.
- Given a `fallback` list whose element is the string `"pause"`, the problem pushed is `fallback list element 0 is "pause" — "pause" is only valid as a whole-tier value` — `pause` is refused inside a list because a list is tried element by element, so a `pause` element would never pause.
- Given a clean selector `"omlx/a"` as the only element, `checkFallbackList` pushes no problem — a legitimate model id passes the element rules.
- Given `checkRetiredSelector("model", "omlx/llama3.1", "claude", problems)` — a provider/model id (the selector carries a `/`) while the backend is `claude` — the problem pushed is `model "omlx/llama3.1" is a provider/model id but the backend is claude, which would run it as a paid claude model — add backend: "pi" beside it`.
- Given a bare (no `/`) selector such as `"llama3.1"` on the `claude` backend, `checkRetiredSelector` pushes no problem — only a provider/model id is the mis-price risk.
- Every pre-existing test passes unmodified; no source file and no other test file change; the project's declared check is green.
