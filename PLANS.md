**Goal.** `startMerge` (src/merge/merge-drain.ts, the single serial task the merge drain launches for one queued change) answers two separate reader questions in one `task = (async () => { … })()` IIFE. The merge-run: when the change starts user-aborted it ends here as "aborted"; otherwise it marks the change `merging` and calls `mergeApprovedChange` (which owns the change's gate under the permit the task acquired), catching `GateDeferredByHold` (a hold that closed the gate — keep the entry, record no failure) versus any other throw (record `lastError`, saving the role state best-effort), and writes the reached outcome into `result`. The settlement: a `settleOne` primitive that queues the post-merge review for a landed "changed" and then `settleMergeOutcome`, plus the `if (!settled)` ground-truth ladder — settle "changed" when this task's own `mergedCommit` event fired, else the reached result (but let the operator's stop win a retriable outcome), else "aborted" under a user abort, else remove the change marker. Every branch reads the same `result`, `settled`, `mergedCommit`, `merge.userAborted`, `author`, `entry`, `v`, `root`, `role`, `usage`, `file` locals, so the two concerns are welded into one body. Lifting each into one named module-private helper lets a name answer each question while the IIFE keeps the shared mutable locals, `settleOne`, and the INV-G6 `finally` slot-free once. Behavior-preserving extraction only.
