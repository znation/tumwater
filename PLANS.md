### OpenCode catalog cache: a foreign entry in `opencode-models.json` is dropped on read instead of throwing out of the poll loop's budget gate and `tumwater status`, and docs/invariants.md gains a section for it (planned 2026-10-20 by the plan role; independent of every eligible plan; touches src/agent/opencode/opencode-catalog.ts + test/opencode-catalog.test.ts + test/status-budget.test.ts + docs/invariants.md)

**Goal.** `readOpencodeCache` (src/agent/opencode/opencode-catalog.ts) checks that `fetchedAt` is a number and that `models` is an object (`isJsonObject`). It does not check the entries, so anything inside `models` reaches callers typed as `OpencodeCatalogModel`. `opencodeModelFree` reads `entry.free` after testing only `entry !== undefined`, so a `null` entry throws a TypeError. `opencodeModelFree` is reached from `pollBudgetGate` (src/gates/budget-gates.ts, through `piPairFree` in src/pi/pi-models.ts; `pollTeamGates` in src/gates/gate-polls.ts calls it with no try), which means the throw escapes the poll loop. It is also reached from `collectBudget` (src/status/status-budget.ts), so it breaks `tumwater status` and the dashboards. `observeOpencodeRun` reads `entry.free` the same way. A wrong-typed field is quietly wrong instead of throwing. `free: "yes"` reads as free to the budget gate, which is the unsafe direction. `efforts: "high"` is a string, and the opencode backend's `entry?.efforts?.includes(thinking)` (src/agent/opencode/opencode-backend.ts) matches substrings of it. On 2026-10-20 the plan role confirmed all three with a scratch test (since deleted). The test wrote `{"fetchedAt":1,"models":{"opencode/m":null,"opencode/s":{"free":"yes"},"opencode/e":{"free":false,"efforts":"high"}}}` and read it back with `readOpencodeCache`. Then `opencodeModelFree(c, "opencode/m")` and `observeOpencodeRun(root, { model: "opencode/m", costUsd: 1 }, …)` threw TypeError, `opencodeModelFree(c, "opencode/s")` returned true, and the `efforts` value's `.includes("hi")` returned true. The cache file is a hand-editable state file, and a failed catalog fetch keeps whatever it holds (`refreshOpencodeCatalog`), so one bad entry stays in place until a fetch succeeds.

**Approach.**
1. src/agent/opencode/opencode-catalog.ts: add an unexported `isOpencodeCatalogModel(value: unknown): value is OpencodeCatalogModel`. It requires `isJsonObject(value)` and `typeof value.free === "boolean"`. Each optional field must be absent or well typed: `inputPerM`, `outputPerM`, `context` and `billedAt` must each be a number with `Number.isFinite`, `images` must be a boolean, and `efforts` must be an array whose every element is a string. Any other field rides along unchecked. `readOpencodeCache` keeps its top-level checks. It returns `models` as a new object that keeps only the entries passing the guard, so a dropped entry reads as a model missing from the cache. That is "not free", the safe direction `opencodeModelFree`'s doc comment already names. Extend `readOpencodeCache`'s doc comment to say so in one sentence. Leave `opencodeModelFree`, `observeOpencodeRun`, `refreshOpencodeCatalog` and `parseOpencodeCatalog` unchanged. The parse of OpenCode's own fetched body is a separate concern and out of scope.
2. test/opencode-catalog.test.ts: append the test "readOpencodeCache drops a foreign catalog entry and keeps the valid ones". Write the file raw: `fs.mkdirSync(path.dirname(opencodeModelsPath(root)), { recursive: true })` (import `path` from node:path), then `fs.writeFileSync(opencodeModelsPath(root), JSON.stringify(...))` on a `tmpdir()` root. Use `fetchedAt: 1` and include:
   - one valid entry, `"opencode/ok": { free: true, context: 1000, efforts: ["high"], extra: 1 }`
   - foreign entries `"opencode/null": null`, `"opencode/num": 7`, `"opencode/yes": { free: "yes" }`, `"opencode/nofree": { context: 1000 }`, `"opencode/ctx": { free: true, context: "big" }`, `"opencode/eff": { free: false, efforts: "high" }`, `"opencode/eff2": { free: false, efforts: ["high", 3] }` and `"opencode/billed": { free: true, billedAt: "soon" }`

   Assert that `readOpencodeCache(root).models` deep-equals `{ "opencode/ok": { free: true, context: 1000, efforts: ["high"], extra: 1 } }`. Assert that `opencodeModelFree(readOpencodeCache(root), "opencode/null")` and the same call for `"opencode/yes"` both return false. Assert that `observeOpencodeRun(root, { model: "opencode/null", costUsd: 1 }, { source: "feature", log: () => {} })` returns null. Import `readOpencodeCache`.
3. test/status-budget.test.ts: append the test "a foreign entry in the opencode catalog cache leaves collectBudget standing, read as not free". Set it up like "collectBudget prices an opencode-free team free (part 6b/7)", except that after `writeOpencodeCache(repo)` you overwrite `opencodeModelsPath(repo)` raw with `{ fetchedAt: Date.now(), models: { "opencode/deepseek-v4.1-flash-free": null } }` (import `fs` and `opencodeModelsPath` from ../src/paths.js). Assert that `collectBudget(…)` does not throw and that `got.budget.free` is false.
   Mutation, applied by hand and reverted: make `readOpencodeCache` return `existing.models` unfiltered. Both new tests should then fail, the status test with the TypeError. Claim in VERIFIED only what you saw.
4. docs/invariants.md: append "## OpenCode catalog cache: a foreign entry reads as an unknown model" after the last section. For the INV prefix, run `grep -n '^### INV-' docs/invariants.md | tail` and read the "was free" notes in PLANS.md's Planned entries. On 2026-10-20, BT had merged, BU (Image-probe cache) was planned, and BV was free. Use the Guarantee / Binds / Pinned by layout with one guarantee: `readOpencodeCache` returns only well-formed catalog entries, so a missing, torn or foreign cache file or entry never throws out of `pollBudgetGate`, `collectBudget` or `observeOpencodeRun`, and a dropped entry reads as not free. It binds `readOpencodeCache` and `isOpencodeCatalogModel`. It is pinned by the two new tests plus "opencodeModelFree: free and unbilled is free; priced, unknown, or billed are not" and "observeOpencodeRun demotes a cached free model on a priced run, once" (the latter shows a valid entry still round-trips). Cite each test by its full name.

**Files touched.** src/agent/opencode/opencode-catalog.ts (`readOpencodeCache`, one new private guard); test/opencode-catalog.test.ts and test/status-budget.test.ts (one appended test each, plus imports); docs/invariants.md.

### QA flow coverage: a failed `qa-coverage.json` write warns instead of failing a run whose merge is already queued (planned 2026-10-20 by the plan role; independent of every eligible plan; touches src/run/run-stage.ts + src/run/run-verdict.ts + test/run-stage.test.ts + test/run-verdict.test.ts + docs/invariants.md)

**Goal.** `recordFlow` (src/run/qa-coverage.ts) writes the qa ledger with `writeJsonAtomic` and does not catch a write failure. Its two callers do not catch it either:
- `stageRunMerge` (src/run/run-stage.ts) calls `recordFlow` after the merge is queued, after the pin, and after the best-effort `merge_queued` event.
- `resolveRunVerdict` (src/run/run-verdict.ts) calls it on the no-change path, before returning `no_change`.

So a full disk, a read-only `.tumwater`, or any other failed ledger write throws out of the run. The catch in `runPhase` (src/runner/runner-run.ts) then turns the outcome into `error` and sets `lastError`. `finalizeRun` (src/run/run-finalize.ts) counts that toward the role's error streak, even when the work was committed and queued. On 2026-10-20 the plan role confirmed this with a scratch test (since deleted). The test was a copy of "a qa flow record from the reply is written into the coverage file" with `failRenameSyncOn(qaCoveragePath(root), "EACCES fake")` installed. `stageRunMerge` rejected with `Error: EACCES fake` while `queueDepth(root)` was 1. A second scratch test called `resolveRunVerdict` with test/run-verdict.test.ts's `makeCtx(root, wt, "qa", { flow: { flow: "status", result: "passed" } })`. Without the fault it returned `no_change` and recorded the flow. With the same fault installed it rejected with `Error: EACCES fake`. The ledger only orders the qa role's flow menu. The run-stage comment beside `logEventBestEffort` already says that observability must not reject a run whose work is queued, and the ledger is in the same position.

**Approach.**
1. src/run/run-stage.ts: wrap the `recordFlow(…)` call in `try { … } catch (err) { ctx.warn(`qa flow "${ctx.flow.flow}" not recorded: ${errorMessage(err)}`); }`. Import `errorMessage` from ../text/text.js. Add a one-line comment saying the merge is already queued and the ledger only orders the qa menu, so a failed write warns rather than failing the run. Its return value and every other step stay as they are.
2. src/run/run-verdict.ts: make the same change at the `ctx.flow && !diagnosis.cutOff` site, keeping that guard as it is, with the same warning text. Leave `recordFlow` and `readQaCoverage` in src/run/qa-coverage.ts unchanged. Their own tests call `recordFlow` directly and expect a write.
3. test/run-stage.test.ts: after "a passed qa flow records no summary", add "a failed qa coverage write warns and the run still ends queued". Set it up as "a qa flow record from the reply is written into the coverage file" does (flow `{ flow: "unit tests", result: "bug" }`). Install `failRenameSyncOn(qaCoveragePath(root), "EACCES fake")` from ./helpers/fs-faults.js, with `qaCoveragePath` from ../src/paths.js, and undo it in a `finally`. Assert that `outcome.result` is `"queued"`, that `queueDepth(root)` is 1, that `readQaCoverage(root)` deep-equals `{}`, and that `calls.warnings` holds exactly one entry matching `/qa flow "unit tests" not recorded: EACCES fake/`.
4. test/run-verdict.test.ts: no test there passes a non-null `flow` yet, so add two tests after "a role runner's prompt-less nothing-to-do is not treated as an answer". Both use `initializedWorktree("qa")` and `makeCtx(root, wt, "qa", { flow: { flow: "status", result: "passed" } })`.
   - "a no_change run records its qa flow": the outcome is `no_change` and `readQaCoverage(root).status?.result` is `"passed"`.
   - "a failed qa coverage write warns and the no_change run stands": run with `failRenameSyncOn(qaCoveragePath(root), "EACCES fake")` installed and undone in a `finally`. The outcome is `no_change`, `readQaCoverage(root)` deep-equals `{}`, and `warns` is exactly one entry matching `/qa flow "status" not recorded: EACCES fake/`.
5. docs/invariants.md: append "## QA flow coverage: a failed ledger write never fails a run" after the last section. For the INV prefix, run `grep -n '^### INV-' docs/invariants.md | tail` and read the "was free" notes in PLANS.md's Planned entries. On 2026-10-20, BT had merged, BU (Image-probe cache) and BV (OpenCode catalog cache) were planned, and BW was free. Use the Guarantee / Binds / Pinned by layout with one guarantee: a `recordFlow` write failure in `stageRunMerge` or `resolveRunVerdict` warns once and the run keeps its `queued` or `no_change` outcome. Binds `stageRunMerge`, `resolveRunVerdict` and `recordFlow`. Pinned by the three new tests plus "a qa flow record from the reply is written into the coverage file". Cite each test by its full name. Leave INV-D2 unchanged: it pins the FLOW parse and the cut-off guard, not the write.

**Acceptance criteria.**
- With the `try` removed from either call site, the matching new failure test fails (the call rejects).
- `npm run test:gate` passes.
- `git diff --stat` shows no src/ file changed except src/run/run-stage.ts and src/run/run-verdict.ts.
