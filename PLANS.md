### Live config reload: a live edit that first routes a seam to opencode seeds the models catalog, as startup does (planned 2026-10-20 by the plan role; independent of every eligible plan; touches src/gates/startup-gate.ts + src/config/config-live.ts + test/config-live.test.ts + docs/invariants.md)

**Goal.** The only place that calls `refreshOpencodeCatalog` (src/agent/opencode/opencode-catalog.ts) is `runStartupCheck` in src/gates/startup-gate.ts (checked with `grep -rn refreshOpencodeCatalog src`), and it calls it only when the *startup* config routes a seam to opencode. The live reload in src/config/config-live.ts (`newLiveConfigReload`'s `poll`) already loops over each backend a live edit newly routes to. For each one it checks the binary, and for claude it seeds the account (`seedClaudeAccount`, guarded by `liveClaudeSeedAttempted`) "exactly as startup would". It does nothing for opencode. So a pi team that live-edits a seam onto opencode gets no `.tumwater/state/opencode-models.json` until it restarts. The budget gate (`readOpencodeCache` in src/gates/budget-gates.ts) reads an absent cache as "every opencode seam NOT free". That means a free DeepSeek seam gets priced against the daily cap and is refused as a free fallback, and the role view and doctor show no catalog for it. This is the opencode half of the newly-routed-backend check that plans/provider-concurrency.md §9 gap 1 added for claude.

**Approach.**
1. src/gates/startup-gate.ts: pull the seed call out of `runStartupCheck` into an exported `seedOpencodeCatalog(root: string, config: TumwaterConfig, opts: OpenCodeSeedOptions & { warn?: (message: string) => void } = {}): Promise<unknown>`. It returns `refreshOpencodeCatalog(root, { providers: opencodeProviders(config), cliBin: resolveBackendBin(config, "opencode").bin, fetch: opts.fetch, now: opts.now, warn: opts.warn })`. Move the "Probe the configured opencode binary" comment into it. `runStartupCheck` keeps its `opencodeSeedAttempted` guard and calls `await seedOpencodeCatalog(root, config, opencodeSeed)`. Startup still passes no `warn`, so startup behavior is unchanged.
2. src/config/config-live.ts: add an optional dep `opencodeSeed?: OpenCodeSeedOptions` to `newLiveConfigReload` (tests only; production callers leave it out), plus a `liveOpencodeSeedAttempted` set next to `liveClaudeSeedAttempted`, with a matching comment. In the newly-routed-backend loop, after the claude branch: `if (backend === "opencode" && !liveOpencodeSeedAttempted.has(deps.root)) { liveOpencodeSeedAttempted.add(deps.root); void seedOpencodeCatalog(deps.root, reloaded.config, { ...deps.opencodeSeed, warn }).catch((err) => warn(\`open code model catalog seed failed: ${errorMessage(err)}\`)); }`. Import `errorMessage` from src/text/text.ts, `seedOpencodeCatalog` from src/gates/startup-gate.ts, and its type `OpenCodeSeedOptions`. Do not await it. `poll()` is synchronous and runs once per scheduler cycle, so a models.dev fetch (bounded by `CATALOG_FETCH_TIMEOUT_MS`) must not stall the loop. The `.catch` stops a rejected refresh from becoming an unhandled rejection, whether or not the in-flight "OpenCode catalog seed" plan has merged. Add opencode to the block comment above the loop: "for claude its account seeded" becomes "its account (claude) or models catalog (opencode) seeded".
3. test/config-live.test.ts: append two async tests. Each builds its reload with `newLiveConfigReload({ root, config: start, mainBranch: "main", runnerSignal: new AbortController().signal, runners, semaphore: new Semaphore(1), opencodeSeed: { fetch, now: () => 1_000 } })`, where `root = makeRepo()`, `writeConfig(root, start)`, `runners = [makeRoleRunner(root, "improve", start)]`. `start` is `defaultConfig()` with `review.enabled = true`. After one `live.poll()` of the unchanged file, each writes `next` with `backends = { opencode: { bin: <tmpdir script "exit 0"> } }` and `review = { ...review, backend: "opencode", model: "deepseek-v4.1-flash-free" }`, calls `live.poll()`, then `await new Promise((r) => setImmediate(r))` so the fire-and-forget refresh settles (an `async` fetch stub plus synchronous cache I/O leaves only microtasks).
   - "a live edit routing a seam to opencode seeds the models catalog once": the fetch counts calls and returns `{ opencode: { models: { "deepseek-v4.1-flash-free": { cost: { input: 0, output: 0 } } } } }`. Assert `calls === 1`, `readOpencodeCache(root).fetchedAt === 1_000` and `.models["opencode/deepseek-v4.1-flash-free"]?.free === true`. Poll again, settle again, and assert `calls` is still 1.
   - "a failed live catalog seed warns instead of crashing the poll": the fetch throws. Assert `poll()` returned without throwing, and that `warnMessages(root)` holds exactly one message starting with `open code model catalog fetch failed` (refreshOpencodeCatalog's existing warning, now routed to the live reload's `warn`).
4. docs/invariants.md: append "## Live config reload: a newly routed opencode backend gets its catalog" after the last section, using the Guarantee / Binds / Pinned by layout. For the prefix, run `grep -n '^### INV-' docs/invariants.md | tail` and read the "was free" notes in PLANS.md's Planned entries. On 2026-10-20 BY had merged and BZ (OpenCode catalog seed) and CA (Claude account seed) were planned, so CB was free. Write one guarantee: the first successful reload that routes a seam to opencode, when the previous config did not, starts one catalog refresh per root per process. That refresh never blocks or throws out of `poll()`, and a failed fetch warns through the reload's event log. Binds `newLiveConfigReload` and `seedOpencodeCatalog`. Pinned by the two new tests, each cited by its full name.

**Acceptance criteria.**

### Flake quarantine: a failed `quarantine.json` write warns instead of throwing out of a check whose re-run just passed (planned 2026-10-20 by the plan role; independent of every eligible plan; touches src/review/known-flakes.ts + test/known-flakes-quarantine.test.ts + docs/invariants.md)

**Goal.** `quarantineTests` (src/review/known-flakes.ts) ends with `saveQuarantine(root, entries)`, a bare `writeJsonAtomic(quarantinePath(root), …)` with no try. It has three callers, and each one runs it right after a re-run of the same tree **passed** (checked with `grep -rn 'quarantineTests(' src`):
- src/merge/merge-to-main.ts `verifyMerge`: the in-lock merge check failed, then passed on the immediate retry. A throw here rejects `mergeToMain` before `setMergeStage(…, "merging")`, so a change whose check is green fails its merge attempt.
- src/review/review-precheck.ts `gateBuildPrecheck`: the gate check failed, then passed on the retry. A throw rejects the gate, so the review attempt errors instead of going on with `outcome = retry.outcome`.
- src/baseline/main-watch.ts `watchOnce`: main's confirming re-run turned a red green. A throw skips the rest of `watchOnce` (the baseline transition handling after the re-run). The poll's `.catch` then logs a misleading "main watch could not check main" and marks the head watched.
Each caller ignores the return value. A full disk or a read-only `.tumwater/state` costs only the quarantine record, so it should not undo a passing check. This is the same best-effort contract `writePostReviews` (src/review/post-merge-review.ts) and the bootstrap latch write (src/gates/bootstrap-gates.ts) already follow.

**Approach.**
1. src/review/known-flakes.ts: in `quarantineTests`, replace the trailing `saveQuarantine(root, entries); return added;` with a try around `saveQuarantine`. On a catch, call `warnEventBestEffort(root, TUMWATER_SOURCE, \`could not write quarantine.json: ${errorMessage(err)}\`)` and `return []`, because nothing was recorded. Otherwise return `added` as before. Import `warnEventBestEffort` and `TUMWATER_SOURCE` from ../events/events.js (known-flakes.ts already imports a type from there, and events.ts imports nothing from src/review, so no cycle) and `errorMessage` from ../text/text.js. Add a sentence to the doc comment: "A failed write warns and returns no tests: the callers run this after a re-run passed, so a lost record must not fail that check." Leave `saveQuarantine`, `markQuarantineFiled` and `releaseQuarantine` unchanged. The latter two run only inside main-watch's `settleQuarantine`, whose try/catch already turns a throw into a "quarantine housekeeping failed" warning.
2. test/known-flakes-quarantine.test.ts: append the test "quarantine: a failed quarantine.json write warns and records nothing instead of throwing". Import `failRenameSyncOn` from ./helpers/fs-faults.js and `warningMessages` from ./fixtures/log-fixtures.js. With `root = tmpdir()`, `const undo = failRenameSyncOn(quarantinePath(root), "disk full")`. In a try/finally that calls `undo()`, assert `quarantineTests(root, ["a"], "out")` deep-equals `[]`, which also proves it did not throw. After the finally, assert `quarantinedTests(root)` deep-equals `[]`. Assert `warningMessages(root)` holds exactly one message starting with `could not write quarantine.json` that includes `disk full`. Then call `quarantineTests(root, ["a"], "out")` again (the fault is undone) and assert it returns `["a"]`.
3. docs/invariants.md: in the existing section "## Flake quarantine: a test that failed then passed on one tree is quarantined until its filed bug leaves ## Open, and a possibly truncated list never counts", add `### INV-BI5: a failed quarantine write warns and never throws out of the check that passed` after INV-BI4, in the same Guarantee / Binds / Pinned by layout. No new letter pair is needed. Guarantee: `quarantineTests` never throws on a failed store write. It warns once per failed call, records nothing, and returns `[]`, so the gate's re-run, the in-lock merge check's re-run and main-watch's confirming re-run go on with their passing result. Binds `quarantineTests`. Pinned by the step-2 test, cited by its full name.

**Acceptance criteria.**
- With step 1's try/catch removed, the new test fails (the call throws `disk full`). With `return []` replaced by `return added`, it fails (it returns `["a"]`).
- The existing tests in test/known-flakes.test.ts, test/known-flakes-quarantine.test.ts and test/main-watch.test.ts pass unchanged.
- `npm run test:gate` passes.
- `git diff --stat` shows src/review/known-flakes.ts as the only changed src/ file.
- The test name cited in INV-BI5 exists verbatim (`grep -rF` it in test/).
