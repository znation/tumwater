# Command reference

Every `tumwater` command and the main flags it takes. `tumwater help` lists every command and
flag; `tumwater help <command>` shows one command's usage. The README's Usage section has the
short version, and [config.md](config.md) covers the settings in `tumwater.json`.

## Start the team

```bash
cd your-project             # a new or existing directory
tumwater init "Build a tiny markdown-to-html converter CLI in Python."
                            # add --template <id> to seed from a bundled starting point
                            # (blank, python-cli, node-cli, static-site); --list-templates
                            # prints the catalog
                            # add --branch <name> to name the branch a new repository starts on (it seeds a new repo only)
                            # add --file <path> to read the brief from a file
                            # add --adopt to adopt an existing repo as-is
                            # a fresh/empty project is seeded with
                            # "bootstrap": {"untilPlansDone": 5}, holding the maintenance
                            # roles until 5 plans are done; remove "bootstrap" from
                            # tumwater.json to end that early
tumwater start              # start the team (Ctrl+C to stop)
tumwater start --gui            # ... and serve the browser dashboard at http://127.0.0.1:7180 from the same process
                                # add --port <n> to serve it on another port (the `tumwater gui --port <n>` twin)
                                # add --all-interfaces and --token <secret> to serve the LAN behind the
                                # auth gate — both forward onto the dashboard child, the `tumwater gui` twins
tumwater start --tui        # ... and host the TUI in this same terminal (the `tumwater tui` view; quitting it stops the team like Ctrl+C)
tumwater start --for 2h     # run for a bounded window (capped at 90d), then finish current work, print a per-role summary of the window, and exit (one window across updates); shown as `stops in …` on status, the TUI, and the dashboard
                            # (add --json to print that summary as one JSON object — tumwater start --for 2h --json)
tumwater start --once       # one full round of runs, finishes the merges it produced, and exits (for cron/CI); exits 3 if a run failed;
                            # add --role <id>[,<id>...] to scope the round to the listed roles (enabled roles only)
                            # add --json to print the round's totals, per-result counts, skipped roles and failures as one JSON object (only with --once or --for)
tumwater start --branch <name>  # merge into that branch instead of baseBranch in tumwater.json or the checked-out branch; it must exist
```

`tumwater gui --port N` serves the dashboard on another port than 7180;
booting with `tumwater start --gui --port N` serves it the same way from the
one-command start.
`tumwater start --gui --all-interfaces --token <secret>` forwards both onto the
dashboard child, exposing the dashboard — and with it the director prompt — to your
whole network behind the token gate, so the one-command start can serve the LAN as
`gui --all-interfaces --token <secret>` would on its own.
